# Выполнить проверку приложения

В независимом поручении начни со свежего контекста, критериев и первичных данных.
Историю автора или смену снимка сообщи координатору. Сохрани код, тесты и
ожидания. Используй выделенные ресурсы, передавай дефекты через координатора.
После исправления повтори сценарий и связанные проверки.

Зафиксируй утверждение, ревизию и артефакт. Порученный новый прогон выполни
через указанную границу. Прошлые данные используй для подготовки и сравнения.
Если нужна только оценка доказательств, примени [$fstack:verify](../verify/SKILL.md). Для готовности
без обязательного прогона используй подходящие данные и выполни недостающие
разрешённые проверки. Для прогона найди проектный сценарий по названию из задачи
и сверь с UI или CLI. Без инструкции восстанови минимальный безопасный путь
по коду и командам; при блокировке назови предпосылку. Сохраняй инструкцию
по поручению через [$fstack:test-setup](../test-setup/SKILL.md).

## Пройти пользовательский сценарий

Проверь версию экземпляра, владельца процесса и порта, авторизацию, данные и
готовность приложения. Выполни действия с изолированными данными, проверь эффект
через UI, API, CLI, файл или состояние. Если ответ лишь принимает запись,
подтверди итог чтением. Для mock укажи исключённую границу.

При проверке установки с разрешением установи точный артефакт в чистом
изолированном профиле реального клиента. Для установленного пакета используй
сценарий без переустановки. В обоих случаях сверь идентичность пакета и
наблюдаемый эффект. Укажи проверенную границу и пропуск установки без разрешения.

## Зафиксировать результат

Сохрани команды, коды выхода, версии, попытки и артефакты. Для изменения вида
сравни тот же сценарий до и после на затронутых платформах, укажи среду, версию
и недоступные платформы. Для состояния хватит снимка; для порядка действий
сохрани запись или кадры с доказательством каждого перехода. Внутренний переход
покажи чтением состояния, трассой или диаграммой по наблюдениям. Соблюдай
права на захват, исключай секреты и лишние данные. При RTK по
[$fstack:rtk](../rtk/SKILL.md) сохрани полный решающий вывод. Ради лога внешнюю запись не повторяй.

Очисти свои ресурсы при успехе и сбое. Проверь сохранность доказательств вне
очищаемой среды. Передай покрытие и статусы «пройдено», «не пройдено»,
«заблокировано», «не запускалось» с причинами и указанием подменённых границ.
