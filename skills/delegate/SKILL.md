# Делегировать работу

[Каталог · Координация](../../docs/skills.md#координация)

Цитата не включает навык. Вне faust-mode применяй только явно вызванные навыки.

Координатор отвечает за результат. Поручай независимый результат или проверку.
Одну связную правку ведёт один владелец от причины до подтверждения.

Для полного обзора перечисли обязательные участки и назначь исполнителя каждому.
Для сравнения нескольких решений заранее определи критерий выбора и общие
условия проверки. При сборе результатов отметь пропущенные участки. Если варианты
измеряли в разных условиях, приведи замеры к одному протоколу перед выбором.
Если берёшь разные части двух решений, прогони критерии уже на их сочетании.

## Выбрать исполнителя

Раздели полномочия и зависимости. Для общего файла, ветки или базы назначь
одного писателя. Согласуй сигнатуры, ошибки и эффекты общего контракта.
Независимые задачи выполняй параллельно в рамках слотов, CPU и памяти.
Разнеси Git-индексы по worktree, изолируй браузер и данные или используй
общий стенд по очереди.

Для каждого нового подагента выбирай глубину по сложности поручения и явным
указаниям пользователя. Для поиска файлов или сверки команд достаточно `low`, для
ограниченной правки с известной проверкой начни с `medium`. Для разбора
взаимодействующих причин или сложного ревью выбери `high` или выше.

В Codex вызывай `spawn_agent` с `fork_turns="none"`, явным `reasoning_effort`
и самодостаточным поручением. Сверь доступные для модели уровни по схеме клиента.
Если для поручения нужна другая модель или клиент требует `model`, передай
поддерживаемый идентификатор.
При `fork_turns="all"` или пропуске `fork_turns` клиент наследует настройки
родителя и запрещает переопределение. Используй этот вариант по явному выбору
пользователя. При отказе подбери поддерживаемые
параметры и назови фактическую замену или укажи, что клиент применил наследование.
Ревьюеру передай требования, ревизию и первичные данные без вердикта автора.

## Передать и принять поручение

В активном faust-mode **первой строкой** попроси прочитать [worker.md](worker.md)
по абсолютному пути установленного пакета. Укажи, что поручение дал активный
координатор, затем результат, критерий, снимок, права и источники. Дай абсолютный
путь к выбранному методу той же копии. Для правки это [implement](../implement/SKILL.md),
для независимой оценки — [review](../review/SKILL.md), для сопровождения
PR/MR — [watch-pr](../watch-pr/SKILL.md). Если пакет недоступен, передай правила текстом.
При отдельном вызове delegate передай только прямо вызванные пользователем методы.

Передай готовый вход с ревизией, изменение контракта — зависимым владельцам,
замечания — автору. В Codex `followup_task` продолжает неактивного агента,
`send_message` доставляет данные работающему. При тайм-ауте сверь состояние
и артефакты. Если связь потеряна, проверь исход записей до передачи другому
владельцу. Освободи слот после подтверждённого результата или передачи.

Сверь diff и [доказательства](../verify/SKILL.md) с критерием. Для дефекта повтори
исходный сценарий, при смене ревизии — затронутые и обязательные проверки.
Один владелец [ведёт MR](../watch-pr/SKILL.md) до согласованного состояния.
В подключённом проекте вне Plan токен памяти и одна операция `stage` остаются
у координатора, исполнитель отвечает на свой хук через `report`.
Укажи пределы проверки, включая недоступную независимую оценку.
