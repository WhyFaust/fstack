# Параметры запуска и проверка результата

Форма аргументов зависит от активного клиента. Перед вызовом сверь схему
доступного инструмента. Явно заданные провайдер, модель, глубина и изоляция
остаются требованиями поручения.

## Запуск исполнителя

| Возможность клиента | Пример выбора | Подтверждение |
| --- | --- | --- |
| Нативный исполнитель с отдельным контекстом | В Codex передай в `spawn_agent` самодостаточное `message`, `fork_turns: "none"` и, например, `reasoning_effort: "low"` | Запуск зарегистрирован, глубина исполнителя совпадает с заданной |
| Отдельный провайдер или worktree через оркестратор | В T3 Code для нового worktree передай `isolation: "worktree"` в `delegate_task`. Для выбранного провайдера сверь каталог и передай поддерживаемые параметры в `target.options` | Сверь провайдера и ревизию рабочего снимка. Продолжи по сигналу завершения клиента |

Если пользователь просит полную историю, проверь наследуемые параметры по
схеме. Если требуемое сочетание недоступно, сообщи об этом до запуска.

## Мониторинг PR

Если клиент предоставляет наблюдение за PR, передай его полный URL. Например,
`watch_pull_request` с `until: "checks"` подходит для ожидания проверок.
После уведомления перечитай PR и сверь статус нужного head. Пока клиент
сам возобновляет работу по событию, отдельные опросы не нужны.

## Браузер

Для указанной вкладки найди её через подключённый браузер и возьми локатор из
свежего снимка. Например, в T3 Code начни с `preview_status`.
Для отдельного прогона через Playwright CLI используй отдельную сессию и
сверь команды по справке закреплённой версии. После действия подтверди
ожидаемое состояние в той же вкладке.
