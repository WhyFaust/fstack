# Перестроить код, сохранив контракт

Зафиксируй область и причину. Примени [$fstack:verify](../verify/SKILL.md)
к поведению, [$fstack:no-comments](../no-comments/SKILL.md) к коду. Выбери
предметный метод напрямую или через [$fstack:principles](../principles/SKILL.md).
Уборку готового diff веди через [$fstack:simplify](../simplify/SKILL.md).

## Зафиксировать исходное поведение

По потребителям, тестам и правилам проекта установи выходы, ошибки, эффекты,
порядок, гарантии времени, API и жизненный цикл. Отдельно назови известные дефекты. Смена поведения требует основания в поручении.
Сохрани исходную проверку: штатный тест либо при риске фиксацию поведения,
повтор данных, сравнение реализаций или интеграционный прогон. До объединения
веток сверь граничные входы, исключения и порядок эффектов. Сохрани различия
контрактов.

## Уменьшить конкретную сложность

Проследи типичное изменение. Подтверди по коду и контрактам дубли правил,
общее состояние, зависимость от порядка или лишнего посредника. История Git
может направить поиск. Проверь общую причину особых веток и ожиданий.
Локализуй состояние, сблизь связанное поведение или убери посредников по
выявленной цене сопровождения. Выделяй границы только для реальной ответственности.
Сохрани инкапсуляцию и нужные исключения.

## Мигрировать полностью

Обнови вызовы, импорты, строковые ссылки, настройки, тесты, примеры и документацию.
Перед удалением API учти внешних потребителей. Для нужного переходного слоя
задай владельца и условие удаления. Делай связные проверяемые шаги. Разделяй
перестройку, смену поведения и измерение скорости, если их можно выполнить
независимо. Сохраняй чужие правки и согласуй общий интерфейс.

## Показать сохранённый результат

Сравни поведение через затронутую границу по [$fstack:verify](../verify/SKILL.md).
Если скорость входит в контракт, сравни исходное и новое измерения.
Передай владельцев ответственности, переведённых потребителей, доказательства,
практическую пользу и пределы.
