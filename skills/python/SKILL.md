# Python

[Каталог · Реализация](../../docs/skills.md#реализация)

Цитата не включает навык. Вне faust-mode применяй только явно вызванные навыки.

Сверь правила проекта, [$fstack:no-comments](../no-comments/SKILL.md) и [$fstack:verify](../verify/SKILL.md).

## Окружение и зависимости

Установи версии Python и ОС, менеджер, lock-файл и команды форматирования, линтинга и проверки типов. Начни со стандартной библиотеки и установленных зависимостей. Меняй зависимости и lock по необходимости. Сверь синтаксис, импорты и API с документацией минимальной и остальных поддерживаемых версий.

## Код и контракты

Отдели расчёты от I/O. Сменный клиент передавай явно. Наследование требует совместимого контракта или фреймворка. Сохрани соглашения об импортах без побочных эффектов. Типизируй контракт, проверяй внешние данные при выполнении. Не скрывай ошибки через `Any`, default или подавление. Лови конкретное исключение для обработки либо перевода через `raise ... from exc`.

Используй `pathlib`, укажи кодировку. Назначь владельца файлов, соединений, процессов и задач. Сбой очистки должен сохранять первичную ошибку. Для subprocess учти код выхода, stderr, таймаут и оболочку.

## Асинхронный код и тесты

В event loop используй `await`, блокирующий I/O вынеси с учётом ограничений потоков. Дождись фоновых задач, обработай ошибку. При отмене освободи ресурсы и передай `CancelledError`. Уточни исход внешней записи после таймаута до повтора.

Через штатный вход проверь наблюдаемый эффект. Разделяй независимые контракты, параметризуй варианты, сохраняй неделимый переход в одном сценарии. Подменяй зависимость по месту использования. В pytest регистрируй очистку сразу после получения ресурса, поскольку сбой до `yield` пропустит код после него. Изолируй данные по запуску и работнику. Scope `session` в pytest-xdist локален процессу. [pytest](https://docs.pytest.org/en/stable/how-to/fixtures.html)
