# Python

Применяй вместе с основным методом работы и правилами репозитория:
fstack:verify-result для доказательств, fstack:no-comments при изменении кода.
Используй существующие инструменты проекта.

## Окружение и зависимости

Установи поддерживаемые версии Python и ОС, активное окружение, менеджер
зависимостей, lock-файл и команды проекта. Используй настроенные formatter,
linter и type checker. Не переноси проект на другой toolchain по предпочтению.

Сначала проверь стандартную библиотеку и существующие зависимости. Изменяй
зависимости и lock по необходимости; читай только относящиеся к задаче записи.
Неясный контракт библиотеки проверяй по первичной документации нужной версии.
Сохраняй совместимость со всем заявленным диапазоном Python. При изменении
синтаксиса, импортов или API стандартной библиотеки проверь их доступность
на минимальной версии и учти удаления и изменения в более новых поддерживаемых
версиях. Локальный запуск подтверждает только проверенную среду.

## Код и контракты

Делай зависимости, данные и владение понятными. Используй простые функции,
предметные типы и композицию без лишних фабрик и иерархий. Соблюдай соглашения
импортов и модулей проекта, избегай побочных эффектов при импорте.

Типы описывают контракт; внешние значения проверяются во время выполнения.
Широкий Any, подавление ошибки и вводящий в заблуждение default не исправляют
неопределённый интерфейс. Сохраняй причину исключения и полезный контекст отказа.

Указывай кодировку текстовых данных и используй pathlib для файловых путей.
У файлов, соединений, процессов и задач должен быть явный владелец и момент
освобождения. Cleanup не должен стирать первичную ошибку. Для subprocess
учитывай код выхода, stderr, смысловой timeout и фактическую оболочку.
