# Python

## Вход и границы

Применяй вместе с основным методом работы и правилами репозитория:
fstack:verify-result для доказательств, fstack:no-comments при изменении кода.
Используй существующие инструменты проекта.

## Порядок работы

### Окружение и зависимости

Установи поддерживаемые версии Python и ОС, активное окружение, менеджер
зависимостей, lock-файл и команды проекта. Используй настроенные formatter,
linter и type checker. Не переноси проект на другой toolchain по предпочтению.

Сначала проверь стандартную библиотеку и существующие зависимости. Изменяй
зависимости и lock по необходимости; читай только относящиеся к задаче записи.
Неясный контракт библиотеки проверяй по первичной документации нужной версии.
Сохраняй совместимость со всем заявленным диапазоном Python. При изменении
синтаксиса, импортов или API стандартной библиотеки проверь их доступность
на минимальной версии и учти удаления и изменения в более новых поддерживаемых
версиях. Локальный запуск подтверждает только проверенную среду.

### Код и контракты

Отделяй предметные правила от чтения и записи: передавай проверенные данные
в функции расчёта, а I/O оставляй в вызывающем коде. Если нужно подменять
способ I/O, передавай функцию или клиент явно. Используй наследование, когда
подтип сохраняет контракт базового типа или этого требует точка расширения
фреймворка. Соблюдай соглашения импортов и модулей проекта, избегай побочных
эффектов при импорте.

Типы описывают контракт; внешние значения проверяются во время выполнения.
Широкий Any, подавление ошибки и вводящий в заблуждение default не исправляют
неопределённый интерфейс. Перехватывай конкретное исключение рядом с операцией,
если можешь обработать его или перевести в ошибку контракта. При переводе
используй `raise ... from exc` с контекстом операции. Остальные ошибки
пропускай вызывающему коду.

Указывай кодировку текстовых данных и используй pathlib для файловых путей.
У файлов, соединений, процессов и задач должен быть явный владелец и момент
освобождения. Cleanup не должен стирать первичную ошибку. Для subprocess
учитывай код выхода, stderr, смысловой timeout и фактическую оболочку.

### Асинхронный код и тесты

В работающем event loop ожидай корутину через `await`. Блокирующий I/O
выноси из цикла с учётом потоковых ограничений клиента. Владелец фоновой
задачи должен дождаться завершения и обработать исключение. При отмене
освободи ресурсы и передай `CancelledError` вызывающему. Если внешний
запрос мог успеть изменить данные до таймаута, сверь состояние перед повтором.

Проверяй наблюдаемый результат через поддерживаемую точку входа. Для независимых
контрактов пиши отдельные тесты. Варианты одного поведения параметризуй с независимыми
начальными данными. Проверки одного неделимого перехода оставляй в одном сценарии. Подменяй
внешнюю зависимость в месте её использования. В pytest регистрируй очистку
сразу после получения каждого ресурса: ошибка подготовки до `yield` пропустит
код после него. При параллельном прогоне разделяй данные по запуску и работнику,
включая записи в общем сервисе. Scope `session` в pytest-xdist действует
в отдельном процессе. [Документация pytest](https://docs.pytest.org/en/stable/how-to/fixtures.html)
