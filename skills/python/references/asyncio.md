# Асинхронное выполнение и отмена

Используй asyncio, если задача и существующий стек требуют конкурентного I/O.
Async-функция сама по себе не делает блокирующий вызов неблокирующим.
Установи, кто владеет event loop и как код вызывается из приложения или библиотеки.

Не запускай вложенный asyncio.run внутри работающего event loop. Блокирующую
библиотеку изолируй поддерживаемым способом; перенос в поток не отменяет её
потоковые ограничения и не гарантирует остановку операции при отмене ожидания.

У каждой задачи должен быть владелец, наблюдающий результат и исключение.
Для связанной группы используй принятый механизм структурированного завершения;
TaskGroup и другие API допустимы только в поддерживаемых версиях Python.
Фоновая работа не должна исчезать из учёта после возврата вызывающей функции.

Отмену обрабатывай как часть протокола завершения. После нужной очистки
сохраняй её распространение; не превращай CancelledError в успешный результат.
Timeout выбирай по контракту операции и учитывай время завершения очистки.

Ограничивай одновременные обращения по возможностям зависимости и среды.
Семафор локального процесса не защищает общую БД от других работников.
Используй fstack:manage-state для записей и fstack:manage-resources для владения.

После таймаута внешняя запись могла завершиться. Сначала установи результат
по состоянию системы, затем решай о повторе. Сохрани первичную ошибку и сообщи
о ресурсах, которые не удалось освободить.

Сверяй API с [документацией asyncio](https://docs.python.org/3/library/asyncio-task.html)
для поддерживаемой версии Python.
