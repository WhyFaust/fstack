# Обновить fstack

Нужны Codex CLI с поддержкой repo marketplace, Git и Python 3.11+ для helper.
Доведи порученное обновление до проверенного пакета и согласованного профиля.
Запрос обновить fstack уже разрешает обычные совместимые действия в этом ходе;
повторное согласие на них не нужно. Запрос проверки разрешает только чтение.
Обнаружение навыка само по себе не разрешает обновление: не проверяй версии
при каждой сессии, не создавай фоновые процессы, расписания или hooks.

## Установить исходное состояние

Найди фактический исполняемый Codex через средства оболочки (`Get-Command codex`
или `command -v codex`), проверь `--version` и поддержку команд через `--help`.
Установи целевой `CODEX_HOME` из активной среды и конфигурации клиента; если он
не задан, проверь стандартный `~/.codex`. Все команды выполняй одним клиентом
с тем же целевым профилем. Не подменяй его отдельным временным профилем при
реальном обновлении пользователя.

```text
codex plugin marketplace list --json
codex plugin list --json
```

Прочитай код выхода, затем форму JSON. Найди marketplace `fstack`, его фактический
источник и установленный `pluginId = "fstack@fstack"`, сохрани исходную версию
и enabled/installed. Не угадывай путь по версии кэша и не выводи весь config
с авторизацией. Отсутствующий плагин требует пути первичной установки через
fstack-setup; не превращай обновление в удаление или замену неизвестного источника.

Для Git marketplace проверь, что источник относится к WhyFaust/fstack,
и сохрани выбранный ref. Личный fork или иной ref не заменяй на main.
Если идентичность источника не установлена, остановись до записи.
Для локального marketplace `upgrade` не получает новые исходники: установи
состояние его Git-клона, ветку и remote. В рамках порученного обновления чистого
клона допустим `git pull --ff-only` из его текущего upstream. Незавершённые
изменения, отсутствие upstream или неизвестное происхождение блокируют эту часть;
не переключай ветки, не сбрасывай правки и не меняй регистрацию marketplace.

## Обновить и проверить установленный пакет

Для зарегистрированного Git marketplace выполняй адресно, последовательно:

```text
codex plugin marketplace upgrade fstack --json
codex plugin add fstack@fstack --json
codex plugin list --json
```

У `upgrade` проверь успешный выход, выбранный marketplace, обновлённый root
и отсутствие ошибок; нулевой exit сам по себе недостаточен. Для локального
источника после подтверждённого обновления клона переходи к `plugin add`.
Не обновляй все marketplace без имени и не устанавливай новый Codex ради навыка.
Контракт JSON уточняй по `--help` фактической версии и
[справке команд Codex](https://learn.chatgpt.com/docs/developer-commands).

После успешного `plugin add` проверь `pluginId`, `name`, `marketplaceName`,
`version` и непустой `installedPath`. Разреши этот путь и используй его как
единственный корень нового пакета. Проверь в нём `.codex-plugin/plugin.json`:
имя `fstack`, совпадение версии с ответом установки, наличие `skills/`,
`skills/fstack-setup/SKILL.md`, его справки `references/configuration.md`,
`scripts/sync_profile.py` и `profile/`. Повторный `plugin list` должен подтвердить
ту же identity/версию в `installed` с `installed = true` и `enabled = true`.
Отсутствие или противоречие этих данных останавливает синхронизацию профиля.
Marketplace source содержит исходники, а не доказательство установки пакета.

При timeout, невалидном JSON или неизвестном исходе сначала перечитай состояние
marketplace и плагина и сопоставь версии и файлы. Не удаляй плагин, не чисти кэш
и не повторяй установку вслепую. Без подтверждённого нового `installedPath`
не запускай helper из прежнего навыка или клона. Недоступность CLI, сети,
Git или поддерживаемого вывода назови конкретным ограничением. Смену источника
ради обхода таймаута не выполняй как часть обычного обновления.

## Согласовать профиль из нового пакета

Прочитай `skills/fstack-setup/SKILL.md` и его `references/configuration.md`
именно внутри подтверждённого нового `installedPath`, затем следуй им.
Не продолжай по старому пути текущего навыка после обновления. Актуальная справка
Setup определяет слои конфигурации, CAS, резервные копии и миграции;
не копируй её значения из прежнего пакета.

До `--apply` сопоставь текущие роли целевого профиля и роли из нового `profile/agents/`
по `model` и `model_reasoning_effort` с явным выбором пользователя и эффективными
переопределениями. Helper копирует TOML целиком: отсутствие конфликта хешей
не означает разрешение сменить личную модель или effort. Для роли без этих полей
учти наследование из действующих слоёв. Неподтверждённая смена модели/effort,
личная правка или конфликт блокируют применение профиля; покажи конкретную
замену и необходимое решение, сохрани уже выполненное обновление пакета.
Не обходи конфликт через `--adopt`, ручную запись состояния или перезапись роли.

Из нового корня пакета выполни последовательно, с явным `--home` целевого профиля:

```text
python scripts/sync_profile.py --home <CODEX_HOME>
python scripts/sync_profile.py --home <CODEX_HOME> --apply
python scripts/sync_profile.py --home <CODEX_HOME>
```

Прочитай первый план до применения, включая конфликты, удаления и
`unmanaged_retired`; проверь выход и JSON каждого запуска. При конфликте
не переходи к apply. Последний dry-run должен подтвердить `status = "unchanged"`.
Сохраняй личные параметры config.toml; если миграции не нужны, файл не меняй.
Необходимые совместимые правки выполняй точечно по новой справке Setup,
с проверкой исходной версии и резервной копией, сохраняя права пользователя.

Проверь роли, управляемый блок AGENTS.md и состояние fstack против нового
пакета; проверь доступную строгую проверку клиента, эффективную конфигурацию
и обнаружение ролей/навыков. Учитывай `AGENTS.override.md`, выключенных агентов,
проектные роли и ограничения. Недоступность проверки не означает успех.
Изолированный `scripts/check_installation.py` проверяет пакет в отдельном профиле,
но не заменяет проверку фактического профиля пользователя и не исполняет роли.
Не запускай модельные задачи или сравнения конфигураций без отдельного поручения.

## Сообщить результат

Укажи версию до/после, источник marketplace, новый installedPath и целевой профиль,
статус плагина, синхронизации и повторного dry-run, фактические модели/effort,
изменённые настройки и путь резервной копии. Если пакет обновлён, а профиль
заблокирован, явно сообщи частичный результат и точную причину. Различай разбор
файлов, обнаружение клиентом, доступность моделей и исполнение ролей:
smoke не доказывает модельное поведение. Для новых инструкций и ролей нужен
новый чат; текущая модель и уже загруженные инструкции от обновления не меняются.
