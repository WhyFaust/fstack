# Обновить fstack

Запрос на обновление разрешает обычные совместимые действия с пакетом и
профилем. Запрос проверки разрешает чтение. Веди штатное обновление
последовательно с одним владельцем. При существенном сбое передавай один
конкретный вопрос. Запускай проверку версии только по запросу.

## Подтвердить целевой пакет

Найди фактический Codex CLI и целевой `CODEX_HOME` по активной среде и
конфигурации клиента (по умолчанию `~/.codex`). Используй их для всех команд.
Один раз прочитай исходное состояние:

```text
codex plugin marketplace list --json
codex plugin list --json
```

Проверь выход и JSON. Найди зарегистрированный marketplace `fstack` и
установленную запись `fstack@fstack`, сохрани её версию и флаги. Отсутствие
установленного плагина относится к fstack-setup. Подтверди источник
WhyFaust/fstack или явно выбранный источник пользователя. Сохрани выбранный
ref. При неизвестном происхождении остановись до записи.

Для зарегистрированного Git marketplace вызови
`codex plugin marketplace upgrade fstack --json`. Продолжай только при exit 0
и валидном JSON, где выбран marketplace `fstack` и `errors: []`.
Явный отказ останавливает обновление. При неизвестном исходе адресно перечитай
целевое состояние. После подтверждения успеха используй root из `upgradedRoots`;
пустой список означает no-op, для которого подходит зарегистрированный root.
Найди пакет по записи marketplace и проверь имя `fstack` и целевую версию в его
`.codex-plugin/plugin.json`.

Для локального marketplace сверь происхождение, ветку и upstream Git-клона.
Для чистого клона используй `git pull --ff-only` по текущему upstream, затем
проверь тот же манифест. Локальные правки, отсутствие upstream и неизвестный
источник блокируют обновление клона. Сохраняй выбранный ref и регистрацию.

Если установленная запись имеет `installed = true`, `enabled = true`, нужную
identity и целевую версию, пропускай установку только при уже доступном
подтверждении `installedPath`, его манифеста и соответствия точному целевому
снимку. Равной версии недостаточно, если содержимое источника могло измениться.
При отсутствии подтверждения, включая `installedPath: null` или обновившийся
локальный источник, выполни `codex plugin add fstack@fstack --json` один раз.
Отдельный аудит ради пропуска add не нужен.
Проверь успешный ответ, `pluginId`, `name`, `marketplaceName`, версию, путь и
манифест по этому пути. Один повторный `codex plugin list --json` после add
подтверждает ту же identity и версию в установленной и включённой записи.
Путь бери из подтверждённого ответа установки или установленной записи.
Если источник изменился в той же версии, точечно сравни известный изменившийся
ресурс, нужный для обновления, с установленной копией. При несовпадении сообщи,
что пакет остался на прежнем снимке, и остановись до синхронизации. При другом
противоречии тоже остановись. Root marketplace и предположение
о каталоге кэша не подтверждают установленный путь.

При таймауте, невалидном JSON или неизвестном исходе перечитай целевое состояние
перед решением о повторе. Сохраняй регистрацию, кэш и профиль. Не повторяй запись
вслепую. Справку CLI открывай при конкретной неопределённости формата или команды.

## Согласовать целевой профиль

Из подтверждённого `installedPath` запусти helper с Python 3.11+:

```text
python scripts/sync_profile.py --home <CODEX_HOME>
```

Проверь выход и JSON, включая `changes`, `removed` и `unmanaged_retired`.
При `status = "unchanged"` профиль согласован, переходи к итогу. При конфликте
остановись и назови причину. Применяй только подтверждённый план. План только
для `AGENTS.md` и `fstack/profile.json` не затрагивает роли и `config.toml`
и не требует Setup или проверки строгой конфигурации клиента.

Если план затрагивает роли, сопоставь только эти роли с явным выбором
пользователя и действующими переопределениями. Проверь `model`,
`model_reasoning_effort`, наследование и эффект удалений. Неподтверждённая смена
модели или effort блокирует применение. При необходимой миграции прочитай
`skills/fstack-setup/SKILL.md` и `skills/fstack-setup/references/configuration.md`
из подтверждённого пакета. Меняй и проверяй только затронутую конфигурацию
с сохранением личных параметров.

Если меняется существующий блок `AGENTS.md`, его источник —
`installedPath/profile/AGENTS.md`, границы — от `<!-- fstack:profile:start -->`
до `<!-- fstack:profile:end -->` включительно. Отличие от нового шаблона штатно,
если SHA-256 старого диапазона совпадает с `links_sha256` из `fstack/profile.json`.
Несовпадение хеша, неверные маркеры или отличающийся блок без состояния остаются
конфликтами. При уже совпадающем блоке файл должен отсутствовать в плане.

До применения сохрани исходные байты изменяемого AGENTS.md в памяти или
защищённом временном месте. Из того же корня пакета запусти
`python scripts/sync_profile.py --home <CODEX_HOME> --apply`.
Helper повторно проверяет состояние, защищает резервную копию и проверяет
параллельные записи. При конфликте остановись без `--adopt` и ручной перезаписи.
Проверь выход, JSON, результат по затронутым файлам и путь резервной копии.
Для изменённого существующего блока прочитай итоговые байты таким же способом.
Проверь тело по новому шаблону с обрезкой
внешних пробелов и окончаниями строк helper, а префикс и суффикс побайтно,
включая Notion и личные инструкции. При расхождении исходного снимка
с резервной копией установи причину и сверяй запись с фактической копией.
После записи один повторный dry-run должен показать `status = "unchanged"`.

## Сообщить результат и завершить

Подтверждённая установленная запись и результат helper подтверждают пакет
и профиль. Обнаружение ролей и навыков и эффективные настройки клиента
проверяй только по отдельному запросу или при конкретном симптоме. Для такой
проверки выполни одну целевую попытку в фактическом профиле с ожиданием
до 10 секунд. При ошибке конфигурации, недоступном RPC или таймауте назови
конкретный пробел и заверши проверку.

Для обычного обновления достаточно шагов выше. Тесты репозитория, полный
аудит файлов, установочный smoke в другом профиле и модельные задачи требуют
отдельного поручения или конкретного симптома.

Укажи версию до и после, источник, установленный путь, профиль и исход плана.
Если были записи, сообщи затронутые файлы, итог проверки, повторного dry-run
и путь резервной копии. Личный текст в отчёт не включай. При блокировке назови
подтверждённый частичный результат и причину. Для загрузки новых инструкций
и ролей нужен новый чат.
