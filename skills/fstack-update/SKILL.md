# Обновить fstack

## Вход и границы

Запрос на обновление разрешает обычные совместимые действия с пакетом и
профилем. Для вопроса об установленной версии достаточно `codex plugin list --json`
в целевом профиле. Для сравнения с доступной версией дополнительно прочитай
регистрацию и манифест подтверждённого источника по его ревизии. Оба запроса
завершаются до команд обновления. Веди штатное обновление
последовательно с одним владельцем. При существенном сбое передавай один
конкретный вопрос.

## Порядок работы

### Подтвердить целевой пакет

Различай официальный Git marketplace с платформенной веткой, полный
локальный архив и локальный Git-клон разработчика. Не запускай helper из
неподтверждённого источника. Для архива проверь происхождение и SHA-256
по [инструкции установки](../../docs/installation.md#через-платформенный-архив)
и сохрани прежний каталог до проверки результата.

Найди фактический Codex CLI и целевой `CODEX_HOME` по активной среде и
конфигурации клиента (по умолчанию `~/.codex`). Используй их для всех команд.
Один раз прочитай исходное состояние:

```text
codex plugin marketplace list --json
codex plugin list --json
```

Проверь выход и JSON. Найди зарегистрированный marketplace `fstack` и
установленную запись `fstack@fstack`. Для существующей регистрации подтверди
WhyFaust/fstack или явно выбранный источник пользователя и сохрани выбранный
ref. При неизвестном происхождении остановись до записи.

Если плагин отсутствует и установка не входит в поручение, сообщи об этом
и закончи до записи.

Для удалённого Git marketplace сверь URL и выбранный ref. Если CLI опускает
ref, прочитай только запись `marketplaces.fstack` в `config.toml` и сверь
`ref_name` в `.codex-marketplace-install.json` зарегистрированного root.
Официальные платформенные ветки `marketplace/<target>` перечислены в
[таблице установки](../../docs/installation.md#через-маркетплейс). Ветка
должна соответствовать ОС и архитектуре клиента. Для сравнения версий
без обновления прочитай манифест из выбранной ветки по подтверждённому Git SHA.

Если зарегистрирован исходный ref или ref не указан, проверь наличие
официальной платформенной ветки. Примени
[порядок перехода](../../docs/installation.md#переход-с-ветки-исходников),
если пользователь уже поручил сменить ref. Иначе предложи этот переход
и сохрани прежнюю регистрацию до решения. Сохраняй другой явно выбранный
источник. При недоступной ветке или ошибке не синхронизируй профиль.

Для зарегистрированной платформенной ветки, в том числе сразу после перехода
с ветки исходников, выполни:

```text
codex plugin marketplace upgrade fstack --json
```

Проверь, что `errors` пуст, а `selectedMarketplaces` содержит только `fstack`.
Используй его обновлённый root из `upgradedRoots`. Если список пуст, используй
подтверждённый root регистрации: клиент мог уже получить этот снимок.
Сверь прежние URL и ref, манифест и платформенный бинарник
`bin/fstack` (Windows: `bin/fstack.exe`) в целевом снимке.
При отсутствии бинарника или несовпадении источника остановись до установки
и синхронизации. При неизвестном исходе перечитай состояние перед повтором.

Перед `plugin add` для любого локального источника проверь, что каталог
содержит соответствующий версии и платформе `bin/fstack` (`bin/fstack.exe`
на Windows). Если бинарника нет или его происхождение не подтверждено,
остановись до установки и синхронизации профиля.

Если плагин отсутствует и установка входит в поручение, установи
`fstack@fstack` из подтверждённой регистрации.
Если регистрации нет, используй
[первичную установку через маркетплейс](../../docs/installation.md#через-маркетплейс).
После установки сверь запись и манифест с подтверждённым источником: идентификатор,
версию, путь и состояние включения. Выполни Setup, если настройка профиля входит
в поручение. Верни результат и закончи эту ветку.

Для уже установленного плагина сохрани версию и флаги и продолжи обновление.

Для локального marketplace из архива выполни ветку обновления полного архива
из справки выше и подтверди новый root. Не вызывай Git в каталоге архива.
Для локального marketplace из Git-клона сверь происхождение, ветку и upstream.
Для чистого клона используй `git pull --ff-only` по текущему upstream, затем
проверь тот же манифест. Для полного runtime из исходников необходима новая
сборка `bin/fstack` (`bin/fstack.exe` на Windows) по руководству разработки
до установки локального пакета. Это путь разработчика; обычному пользователю
предложи платформенную ветку Git marketplace. Не используй старый
бинарник с новой версией исходников. Локальные правки, отсутствие upstream и неизвестный
источник блокируют обновление клона. Сохраняй выбранный ref и регистрацию.

### Подтвердить установленный снимок

Для Git marketplace перечитай `codex plugin list --json` после обновления.
Codex может обновить установленный пакет при обновлении marketplace, сохранив
`enabled`. Сверь identity, версию из нового манифеста и исходный `enabled`.
Используй `installedPath` из ответа клиента, если он есть. Если CLI показывает
установленную версию, но не возвращает путь, проверь стандартный каталог
`<CODEX_HOME>/plugins/cache/fstack/fstack/<версия>`. Подтверди, что путь внутри
кэша целевого профиля, и побайтно сверь манифест, платформенный бинарник и
файлы `profile/` с обновлённым root. Если источник менялся без смены версии,
сверь также известные изменения в поставке, включая добавление или удаление
метода, содержимое его справки или хука. Если состав изменений неизвестен,
сравни относительные имена и содержимое поставляемых файлов с целевым снимком.
Только после подтверждения переходи к согласованию профиля. При расхождении флага `enabled` остановись и сообщи
о расхождении. Если версия или файлы не совпадают и плагин был включён,
проверь условия переустановки ниже. Если плагин был выключен, остановись до
`plugin add`, поскольку эта команда включает плагин.

Для локального источника или несовпавшего установленного снимка используй
[порядок переустановки](references/reinstall.md). Если потребуется `plugin add`
для выключенного плагина, остановись до записи. При неизвестном результате
прочитай состояние перед повтором.

### Согласовать целевой профиль

Из подтверждённого установленного пакета выполни `bin/fstack profile --home <CODEX_HOME>`.
Проверь код выхода и JSON, включая `changes`, `removed` и `unmanaged_retired`.
Сообщи об оставшихся неуправляемых ролях, сохрани их файлы. После этого при
`status = "unchanged"` переходи к результату. Для непустого плана открой
[порядок применения, сохранения моделей и проверки миграции](references/profile.md)
до записи. При конфликте остановись и сообщи причину.

## Проверка и результат

### Сообщить результат и завершить

Подтверждённая установленная запись и результат helper подтверждают пакет
и профиль. Обнаружение ролей и навыков и эффективные настройки клиента
проверяй только по отдельному запросу или при конкретном симптоме. Для такой
проверки выполни одну целевую попытку в фактическом профиле с ожиданием
до 10 секунд. При ошибке конфигурации, недоступном RPC или таймауте назови
конкретный пробел и заверши проверку.

Для обычного обновления достаточно шагов выше. Тесты репозитория, полный
аудит файлов, установочный smoke в другом профиле и модельные задачи требуют
отдельного поручения или конкретного симптома.

Укажи версию до и после, источник, установленный путь, профиль и исход плана.
Если были записи, сообщи затронутые файлы, итог проверки, повторного dry-run
и путь резервной копии. Личный текст в отчёт не включай. При блокировке назови
подтверждённый частичный результат и причину. Для загрузки новых инструкций
и ролей нужен новый чат.
