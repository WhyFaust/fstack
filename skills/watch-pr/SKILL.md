# Проверить и сопровождать PR/MR

[Каталог · Ревью и доставка](../../docs/skills.md#ревью-и-доставка)

Цитата не включает навык. Вне faust-mode применяй только явно вызванные навыки.

Установи проект, PR/MR, ветки и порученную точку остановки. Для разового
статуса сними текущий снимок. При сопровождении один владелец ведёт ветку до
результата или блокировки. Используй инструменты PR/MR активного клиента.
Для GitLab сверь доступный MCP и условия [glab](../glab/SKILL.md).

## Проверить актуальную ревизию

Сверь head/base, draft, конфликты, обсуждения, approvals, обязательный CI,
последние попытки и mergeability. Для синтетического коммита проверь source и
target. Устрани разрешённые конфликты и блокирующие замечания. Читай первичный
лог сбоя, исправь причину или обоснуй retry временного отказа. После push или
смены target перечитай head, CI и approvals. Жди итог CI на исправленной ревизии.

## Назначить роли MR

В Draft сохрани действующие назначения. Пропуски заполни по поручению, правилам
и Code Owners. Для исполнителя подтверди владельца или автора, для ревьюера —
право на область. Проверь `assignees` и `reviewers` после записи и перед Ready.
Укажи отсутствующую роль и продолжи доступные этапы.

## Полный цикл GitLab MR

1. Найди открытый MR по паре проектов и веток, включая fork. При отсутствии
   опубликуй первый содержательный коммит и создай Draft с явными source/target
   по [шаблону проекта](../implement/SKILL.md#подготовить-pr-или-mr). Проверь
   проект, IID и URL, последующие правки публикуй в ту же ветку. При неопределённом
   исходе перечитай ref и MR. У готового MR сохрани Ready: исключи из новых
   записей маркеры `Draft:`, `fixup!`, команду `/draft`. Подтверди текущий
   head и `draft=false`. Возврат в Draft требует поручения или правила проекта.
2. На текущем head выполни обязательные локальные проверки, целевой прогон и
   очистку по правилам проекта. Опубликуй head и обнови описание по diff.
   Если цель Draft, подтверди состояние и остановись. Для Ready/Merged проверь
   назначения, зафиксируй локальные результаты и сними Draft по правилам проекта.
   Если обязательный MR pipeline доступен только в Ready, запусти его после
   перехода. Для CLI: `glab mr update IID --ready --repo TARGET_PROJECT`.
   Подтверди head и `draft=false`.
3. Сверь `head_pipeline` и MR pipelines по ID, project, source, ref и SHA.
   Проверь jobs, последние попытки и downstream. При отсутствии обязательного
   pipeline после Ready проверь очередь и правила, запусти его при полномочиях,
   подтверди ID и head. Для fork сверь конфигурацию и права на ресурсы цели.
   Для train проверь MR pipeline до постановки, после — pipeline поезда.
4. Установи обязательность manual, skipped, canceled и отсутствующих jobs.
   Разрешённую обязательную ручную job запусти по ID и подтверди. Дождись
   проверок, запиши итог в MR. Выполни доступный разрешённый
   [approval](../merge/SKILL.md) до ожидания остальных, назови нужного ревьюера.

Для `gitlab-ci-action` передай JSON через stdin: `expected_head`/`head` и
`expected_target`/`target` — ожидаемые и текущие SHA, `draft`,
`pipeline_required`, `may_start` — логические значения. В `pipeline` укажи
статус GitLab, подтверждённое `absent` или `unknown` при неполном чтении.
Для обязательной ручной job укажи `required_manual_job_id`. Перед записью
перечитай GitLab и проверь право на эффекты CI. Без запускателя порядок тот же.

## Остановить серию записей при отказе

Каждую запись подтверди до следующей. При первом отказе Guardian останови
всю серию, включая поручения исполнителям. Перечитай причину и состояние
затронутых MR. Продолжай доступные чтения. Возобнови запись после устранения
причины, при необходимости запроси разрешение на конкретное действие.

## Сообщить статус

Дай head, ссылки на CI и обсуждения, оставшийся шаг. При сопровождении используй
мониторинг клиента, если он доступен. Сверяй head после уведомления. Заверши
ожидание при достижении цели, блокировке или по просьбе остановиться. Для обязательного
отчёта выполни [check](../review/references/cycle.md) по текущим base и head.
При настройке ожидания сверь [пример мониторинга](../delegate/references/client-tools.md#мониторинг-pr).
Для точки Merged передай проверенный SHA в [merge](../merge/SKILL.md).
