# Подготовить план выбранного улучшения

## Вход и границы

Возьми выбранную проблему, путь к плану или ID из backlog. Установи ожидаемый
результат, полномочия, ограничения проекта и затронутых потребителей. Исследуй
только то, что нужно для этого плана. При планировании исходники, зависимости
и общие ресурсы сохраняются. Если нужны кандидаты и их приоритеты, начни с
[аудита кодовой базы](../improve-codebase/SKILL.md).

## Порядок работы

Найди действующий индекс и план той же причины. Для существующего плана
прочитай [правила сверки](../improve-codebase/references/reconciliation.md#актуальность-плана):
проверь исходный снимок, изменения в HEAD, staged, unstaged и untracked,
потребителей и доказательства. Если проблема уже решена, обнови статус
с подтверждением. Для нового плана зафиксируй ветку, полный SHA и базу сравнения, состояние
индекса, рабочего дерева и untracked. Для значимых локальных входов сохрани
пути и хеши либо согласованный снимок. Вне Git опиши доступный снимок
и его ограничения.

Составь план по [шаблону](../improve-codebase/references/plan-template.md).
Сверь правила проекта, границы, потребителей, ограничения совместимости,
проверочные команды и их побочные эффекты. Выведи предпосылки, допустимую
область, способ приёмки и признаки успеха из живого проекта. Подтверждённому дефекту соответствует план исправления,
гипотезе — различающее наблюдение и решение по его исходу. Существенный
выбор интерфейса проработай через fstack:design-change, порядок зависимых
результатов — через fstack:plan-work. Неизвестные данные сначала ищи в
проекте. Уточняй только выбор, который меняет результат.

Отдай план в запрошенном формате. При записи продолжай существующие индекс,
нумерацию и расположение. Если соглашения нет, используй `plans/`, а когда
этот каталог занят другим назначением — `advisor-plans/`. Сохраняй чужие
документы, прежний ID и историю основания. В артефактах оставляй только
нечувствительные выдержки, тип и место секрета без значения.

## Проверка и результат

Проверь, сможет ли исполнитель, видя план и указанный снимок, определить
границы, пройти этапы и отличить успех от отказа. Для существенного плана
получи независимое ревью по fstack:review-change в рамках разрешённой
оркестрации или укажи пробел. Верни план, основание, открытые вопросы и
непроверенные предпосылки. Если реализация уже поручена, продолжай по
[правилам передачи](../improve-codebase/references/reconciliation.md#передача-в-реализацию)
с доступным артефактом и проверенными зависимостями. Запрос только на план
завершается его передачей.
