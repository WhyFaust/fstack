# Спланировать работу по выбранному ID

[Каталог · Планирование](../../docs/skills.md#планирование)

Цитата не включает навык. Вне faust-mode применяй только явно вызванные навыки.

Работай с одним уже выбранным ID. Уточни его, если запрос оставляет несколько вариантов. Результат этапа состоит из плана и свидетельств его актуальности. Оставь реализацию продукта следующему этапу.

## Установить отправную точку

Найди формулировку ID, критерий приёмки, запись в индексе и прошлые планы по нему. Сопоставь их с текущим кодом, тестами и доступными результатами проверок. Отдельно укажи выполненное, оставшуюся работу и сведения, требующие подтверждения. Если цель уже достигнута, приведи проверяемое основание и зафиксируй завершение планирования.

Запиши ветку или detached HEAD, базовую ссылку и разрешённый SHA базы, SHA HEAD. Укажи, как выбрана база сравнения. Различи staged, unstaged и untracked по выводу Git. Для важных файлов зафиксируй контрольные суммы текущего содержимого, для удалённых файлов отметь удаление. По этому снимку исполнитель должен распознать изменение исходных условий. Вне Git используй доступную версию поставки или снимка и перечень затронутых файлов с контрольными суммами.

## Описать ближайший шаг

Если техническое предположение меняет план, найди наблюдение, которое различает варианты. Выполни доступную обратимую проверку в рамках поручения. Если для неё нужен недоступный стенд или право, поставь её первым шагом и укажи, как при каждом исходе изменится план.

Сформулируй небольшой шаг с наблюдаемым результатом. Укажи точку входа, затрагиваемые компоненты, входные данные, признак успеха и хотя бы один случай отказа с ожидаемым поведением. Перечисли команды для исполнителя с рабочим каталогом, предпосылками и эффектами. Если для шага нужен секрет, в плане и примерах команд укажи только его назначение и имя переменной или место хранения. Отдели уже полученные свидетельства от ожидаемых результатов этих команд.

Проверь зависимости по обе стороны изменяемой границы. Найди владельца каждого контракта совместимости и его потребителей по коду или проектной документации. Если владелец неизвестен, оставь конкретный вопрос и укажи, чьё решение нужно. Перед следующей стадией запланируй проверку через реальную точку интеграции: задай вход, ожидаемый эффект у потребителя и условие, при котором работу следует остановить.

## Передать план

Сохрани новую запись по принятому в проекте пути либо верни план в ответе, если места хранения нет. При обновлении индекса сохрани историю ID и ссылки на прежние решения. Перед записью перечитай индекс и затрагиваемую запись, учти параллельные правки. Сохрани чужие планы. Для существенного плана организуй независимое ревью в пределах выданных разрешений либо зафиксируй пробел, предмет проверки и стадию, до которой его нужно закрыть.

При необходимости используй точки [аудита](../audit/SKILL.md), [планирования](../plan/SKILL.md) и [ревью](../review/SKILL.md) для передачи результата. Ссылки сами по себе не включают эти методы. Заверши указанием выбранного ID, расположения плана и проверки, по которой исполнитель решит, можно ли переходить дальше.
