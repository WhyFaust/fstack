# Цикл ревью по коммитам

Запускай из проверяемого Git-репозитория. Укажи полные SHA целевой ветки и
ветки изменения. Команда читает запрос в UTF-8 и возвращает JSON. Отчёт держи
в артефакте задачи или в согласованном хранилище PR/MR.

```sh
/bin/sh /path/to/fstack/launchers/fstack.sh review request.json
```

```powershell
& 'C:\path\to\fstack\launchers\fstack.ps1' review request.json
```

Без имени файла команда читает stdin. В локальном checkout собранный
бинарник используй с `--package /path/to/fstack`.

## Запросить план

```json
{"action":"plan","revision":{"base":"BASE_SHA","head":"HEAD_SHA"}}
```

Если есть прошлый отчёт, передай его объект в `previous`. Замени значения
`BASE_SHA` и `HEAD_SHA` фактическими SHA. При действии `review` проверь
`git diff <plan.from> <plan.revision.head>`, открытые замечания из `open`
и затронутых потребителей. В `guidance` команда возвращает `REVIEW.md`
из целевого коммита, если там есть этот файл.

| Значение | Действие |
| --- | --- |
| `full` | Весь diff от общей базы. Применяется на первом проходе, при смене базы, переписанной истории или незавершённой проверке. |
| `delta` | Правки от предыдущего head при продолжении той же истории. |
| `findings` | Тот же снимок. Проверь новое основание закрытия открытого пункта. |
| `reuse` | Завершённый отчёт для того же снимка. |
| `owner` | После третьего незавершённого раунда передай состояние владельцу. |

Полный или повторный проход учитывается после записи результата. Решение по
открытому замечанию на том же снимке сохраняет номер раунда.
Для расширившегося риска передай `"mode":"full"`. После решения владельца о
новом подходе передай `"mode":"restart"` вместе с прошлым отчётом. Начнётся
полный проход с первого раунда и сохранёнными замечаниями.

## Записать результат

В запросе `"action":"record"` передай `plan` из ответа, те же `previous` и
`mode`, если они применялись, и объект `outcome` со следующими полями.

| Поле | Содержание |
| --- | --- |
| `complete` | `true` при завершённом проходе, `false` при существенном пробеле. |
| `evidence` | Строка с проверенными командами, исходами и ограничениями. |
| `findings` | Подтверждённые дефекты. Поля `id`, `path`, `line`, `summary`, `evidence`. |
| `decisions` | Проверенные решения по открытым пунктам. Поля `id`, `resolution` (`fixed` или `dismissed`), `evidence`. |

Массивы можно опустить. Выбирай ID причины из строчных букв ASCII, цифр и
дефисов. Сохраняй ID при смещении строк и повторном проявлении причины.
Открытый пункт остаётся в отчёте до решения. Возьми объект `report` из ответа
и сохрани его целиком для следующего шага.

## Проверить готовность

Передай `"action":"check"`, объект `revision` с актуальными SHA и `report`
из доверенного артефакта. Код 0 и статус `ready` подтверждают готовность
ревью. При коде 1 прочитай JSON со статусом (`stale`, `findings`,
`incomplete` или `owner`) и открытыми ID. Ошибка входа или Git сообщает
причину в stderr. В CI получай SHA из события площадки и загружай отчёт
из защищённого источника. Обязательные проверки и одобрения подтверди на площадке.
