# Цикл ревью по коммитам

Из проверяемого репозитория передай запрос в UTF-8 с полными base/head SHA.
Команда возвращает JSON. Отчёт храни в доверенном артефакте задачи или PR/MR.

```sh
/bin/sh /path/to/fstack/launchers/fstack.sh review request.json
```

```powershell
& 'C:\path\to\fstack\launchers\fstack.ps1' review request.json
```

Без имени файла команда читает stdin. В локальном checkout собранный
бинарник используй с `--package /path/to/fstack`.

## Запросить план

```json
{"action":"plan","revision":{"base":"BASE_SHA","head":"HEAD_SHA"}}
```

Прошлый отчёт передай в `previous`. Для `review` проверь
`git diff <plan.from> <plan.revision.head>`, открытые замечания и потребителей.
Поле `guidance` содержит правила `REVIEW.md` из целевого коммита, если они есть.

| Значение | Действие |
| --- | --- |
| `full` | Весь diff от общей базы. Применяется на первом проходе, при смене базы, переписанной истории или незавершённой проверке. |
| `delta` | Правки от предыдущего head при продолжении той же истории. |
| `findings` | Тот же снимок. Проверь новое основание закрытия открытого пункта. |
| `reuse` | Завершённый отчёт для того же снимка. |
| `owner` | После третьего незавершённого раунда передай состояние владельцу. |

Запись прохода учитывает раунд. Решение по замечанию на том же снимке сохраняет
его номер. При расширении риска выбери `"mode":"full"`. После согласованной
смены подхода `"mode":"restart"` с прошлым отчётом начнёт полный проход
с первого раунда и сохранит замечания.

## Записать результат

В запросе `"action":"record"` передай `plan` из ответа, те же `previous` и
`mode`, если они применялись, и объект `outcome` со следующими полями.

| Поле | Содержание |
| --- | --- |
| `complete` | `true` при завершённом проходе, `false` при существенном пробеле. |
| `evidence` | Строка с проверенными командами, исходами и ограничениями. |
| `findings` | Подтверждённые дефекты. Поля `id`, `path`, `line`, `summary`, `evidence`. |
| `decisions` | Проверенные решения по открытым пунктам. Поля `id`, `resolution` (`fixed` или `dismissed`), `evidence`. |

Массивы необязательны. Сохраняй ID причины (строчные ASCII-буквы, цифры, дефисы)
при смещении строк и повторном проявлении. Передавай полученный `report` целиком.

## Проверить готовность

Передай `"action":"check"`, `revision` с актуальными SHA и доверенный `report`.
В CI бери SHA из события площадки. Код 0 с `ready` подтверждает ревью. При
коде 1 проверь JSON со статусом и открытыми ID, при ошибке входа или Git — stderr.
Для готовности с обязательным CI добавь поле `verification`:

```json
{
  "required": ["build", "integration"],
  "results": {"build": {"head": "HEAD_SHA", "status": "success"}}
}
```

Возьми `required` из правил проекта, `results` — из последних доверенных попыток CI.
Каждое обязательное имя требует `success` на проверяемом head. Иначе при
готовом ревью код 1 и `checks_blocked` вернут причины в `blocked_checks`: `missing`,
`stale` или `not_successful`. Без `verification` проверяется только ревью.
Одобрения и условия слияния проверь на площадке.
