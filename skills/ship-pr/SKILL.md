# Выполнить разрешённое слияние

## Установить разрешение и готовность

Из действующего поручения установи разрешение на merge или auto-merge,
целевой репозиторий, PR/MR, ветку назначения и способ. Уже выданное разрешение
действует; работа с кодом или создание PR сами по себе его не предоставляют.
Если для операции GitLab нужен переход с MCP на CLI, до первого вызова
прочитай fstack:glab и проверь условия перехода по этому навыку.

До слияния используй fstack:watch-pr только для чтения. Проверь текущие
head/base, approvals, обсуждения, обязательные проверки и возможность слияния.
Ревью должно относиться к текущему изменению. Поздние правки требуют проверки
затронутого. Если пользователь объявил собственное ревью, дождись его результата.

Установи все PR/MR и ревизии, которые затронет операция, и проверь, что
поручение охватывает каждый эффект. В стеке GitHub слияние среднего PR
также сливает нижние незавершённые PR и может изменить базу или head
оставшегося стека. Зависимые PR/MR проводи от нижнего готового изменения.
После каждого шага перечитай состояние следующего. Целевую ветку, rebase
и чужую историю нельзя менять без соответствующего поручения.

## Выполнить слияние

До вызова auto-merge проверь, какую ревизию сможет слить сервис. Если
разрешение ограничено конкретным head, а сервис допускает слияние новых
push, auto-merge выходит за это разрешение.

Если разрешение ограничено конкретной ревизией, передай ожидаемый SHA
в операцию, которая на стороне forge гарантирует его проверку при слиянии.
Для стека эта гарантия нужна для каждой ревизии, на которую ограничено
разрешение. Если доступная операция её не даёт, остановись до записи.
В остальных случаях тоже передавай проверенный head, если операция это
поддерживает. При несовпадении ревизии вернись к оценке готовности и разрешения.
Соблюдай применимые защиты ветки.

## Подтвердить результат

После действия перечитай состояние каждого затронутого PR/MR. Для слитых
сверь коммит слияния и ветку назначения, для оставшихся в стеке проверь head
и base. При очереди или включённом auto-merge сообщи состояние ожидания.
Статус «слито» требует подтверждения в forge.

При частичном отказе или потере ответа сначала установи исход для каждого
затронутого PR/MR. Перед повтором сверь готовность и разрешение для оставшегося
набора по его текущим ревизиям. Наблюдай очередь только в порученном режиме.
