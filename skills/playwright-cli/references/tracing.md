# Трассировка

Trace помогает связать действие с DOM, сетью, консолью и временем. Для
демонстрации пользователю подходит [видео](video-recording.md), для одного
визуального состояния — скриншот.

Открой свою сессию до записи, начни trace до интересующего действия и останови
после. Прочитай свежий снимок перед выбором element ref.

```bash
playwright-cli -s=diagnosis open https://example.com
playwright-cli -s=diagnosis tracing-start
playwright-cli -s=diagnosis snapshot
playwright-cli -s=diagnosis click e5
playwright-cli -s=diagnosis tracing-stop
playwright-cli -s=diagnosis close
```

Пути бери из фактического вывода. Обычно CLI создаёт каталог
`.playwright-cli/traces/` с `trace-*.trace`, `trace-*.network` и `resources/`.
Сохраняй комплект: trace содержит действия, снимки DOM, кадры и временные
данные, network — запросы и ответы, resources — содержимое для восстановления.

## Анализ результата

Для упавшего шага сопоставь состояние до/после, locator, ответ сервиса,
ошибки консоли и тайминги. Для скорости используй waterfall и сопоставимые
условия по verify-result; сама запись добавляет накладные расходы.

Trace может содержать DOM с личными данными, заголовки авторизации и тела
ответов. Перед передачей проверь содержимое и назначение получателя.
Не записывай реальные платежи или внешние изменения только ради доказательства.
Наличие трассы не означает, что сценарий или очистка завершились успешно.

Динамическое содержимое может воспроизводиться неполно. Фиксируй версию,
ревизию, входной сценарий и ограничения. Очистку делай адресно после сохранения
нужных доказательств; не удаляй чужие traces по общему возрастному правилу.
