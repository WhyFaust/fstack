# Поиск документации

## Вход и границы

Выдели конкретный неизвестный контракт. Для фактического сбоя установи версию,
которую загрузил процесс или использовал прогон. Manifest может описывать диапазон,
а lock-файл — запланированную установку. Для проектирования используй поддерживаемый
диапазон версий или указанную пользователем целевую версию. Уже прочитанный подходящий источник используй повторно. Само упоминание
библиотеки не требует нового поиска.

## Порядок работы

### Поиск

Уточни вопрос о контракте и выбери доступный интерфейс Context7. Исключи
из запроса секреты, личные данные и закрытый код. Если пользователь передал
корректный ID библиотеки, сразу запрашивай документацию.

- Через MCP прочитай схемы инструментов поставщика. Получи ID через
  `resolve-library-id` / `resolve_library_id`, затем запроси документы через
  `query-docs` / `query_docs`.
- В настроенном CLI выполни `ctx7 library "<имя библиотеки>" "<вопрос о контракте>"`,
  затем `ctx7 docs "<ID библиотеки>" "<вопрос о контракте>"`. Для проверки опций
  используй `ctx7 --help`. [Context7 CLI](https://github.com/upstash/context7/tree/master/packages/cli).

Для конкретной версии выбери ID из ответа поиска. Если нужной версии нет,
обратись к официальной документации или исходникам этой версии.

До трёх обращений к каждому инструменту на вопрос обычно достаточно. При недостаточном
результате переходи к первоисточнику.

### Недоступность источника

Если выбранный интерфейс недоступен, используй уже настроенный CLI или открой
официальный источник нужной версии. Команды `ctx7 setup`, `login` и `remove`
меняют настройки или авторизацию.
При исчерпании квоты не меняй транспорт для обхода ограничения. Кратко обозначь
существенную проблему доступа и фактически использованный источник.

## Проверка и результат

В ответе укажи версию, применимый контракт и прямую ссылку. Отделяй вывод из исходников
от задокументированной гарантии. Если актуальный источник недоступен, обозначь
непроверенный факт и его влияние на решение.
