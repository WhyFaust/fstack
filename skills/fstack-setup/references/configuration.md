# Согласовать настройки полного профиля

Setup выполняет этот шаг за пользователя. Обычный запрос проверки не разрешает
запись; запрос установки полного профиля разрешает необходимые совместимые правки,
а запрос настройки — только явно выбранные параметры.
Не заменяй весь config.toml содержимым примера и не меняй сторонние настройки.

## Определить действующие значения

Прочитай применимые слои конфигурации: пользовательский, активный именованный
профиль, проектный и управляемые ограничения. Выводи только нужные поля, без
авторизации и секретов. Уточни доступные модели и reasoning по фактическому
каталогу клиента, затем используй [политику выбора](../../delegate-work/references/model-routing.md).

При доступном [Codex app-server](https://learn.chatgpt.com/docs/app-server) используй
config/read с includeLayers=true и model/list со всеми страницами. Различай
значение в пользовательском файле, значение по умолчанию клиента и итог после
применения более приоритетного слоя. Не запускай модельную задачу ради каталога.

Существующие model, effort, лимиты и провайдеры сохраняй, если пользователь
не поручил их заменить. Явно выбранные в беседе значения имеют приоритет над
прежними предпочтениями в той же области; не спрашивай их повторно.
Поставляемые роли закрепляют `gpt-6.1-sol` и свой effort: auditor/verifier `low`,
coder/allure_analyst `medium`, reviewer `high`. Поля TOML роли перекрывают параметры
spawn и общие `[agents]` defaults. Поэтому новый единый выбор модели для профиля
проверяй и в координаторе, и в каждой роли; правки только `model` и
`agents.default_subagent_model` недостаточны.

При полной установке для отсутствующих общих значений используй
[пример](../../../profile/config.example.toml): координатор `gpt-6.1-sol` с `low`,
агенты включены, лимит 2, default исполнителей `gpt-6.1-sol` с `medium`.
Проверяй доступность в клиенте, не закрепляй непроверенную замену при недоступном
каталоге. Существующий явный выбор пользователя сохраняй и показывай несовпадение
с ролью. Отсутствие общего модельного ключа не снимает закрепления файла роли.
При изменении выбранных настроек не заполняй остальные пробелы конфигурации.
approval_policy и sandbox_mode не меняй ради установки fstack.

Проверь явное отключение агентов, роли из других слоёв и старые ссылки на
python_coder. Настройки, перекрывающие выбранную роль или модель, покажи как
конкретное несовпадение. Текст новой роли не отменяет более приоритетный config.
Не удаляй чужие роли или ограничения, чтобы скрыть конфликт.

## Разрешить конфликт синхронизации

До записи проверь выключенных агентов и роли из более приоритетных слоёв.
Подготовь точечное исправление. Запрашивай решение только для замены, которую
ещё не разрешили. Общие `AGENTS.md` и `AGENTS.override.md` не настраиваются
через Setup. Само наличие override не мешает синхронизации ролей.

Единственное изменение глобального `AGENTS.md` helper выполняет при миграции
состояния `schema: 1` в `schema: 2`: удаляет диапазон прежнего блока по маркерам
и `links_sha256`, сохраняя остальные байты. Изменённый или отсутствующий блок
вызывает конфликт до любых записей. Сначала установи причину расхождения;
не меняй хеш состояния и не перезаписывай личные инструкции ради продолжения.
Без состояния владения блок не удаляется. Порядок восстановления описан
в [контракте профиля](../../../docs/codex.md#миграция-глобальных-инструкций).

При переходе со старого набора coder заменяет python_coder, добавляется verifier.
Прочитай `removed` и `unmanaged_retired` в плане helper. Он удаляет только
неизменённую роль, которой владеет по сохранённому хешу. Пользовательская старая
копия не удаляется; вручную изменённая управляемая роль становится конфликтом.

`--adopt` допустим только с `--apply` при первом принятии отличающихся существующих
ролей. Он не разрешает удалять изменённый старый блок инструкций.
Сначала покажи конкретные файлы и проверь разрешение на замену.
Для уже управляемого, вручную изменённого файла `--adopt` не является force.
После пользовательской настройки роли сохраняй её и учитывай конфликт при обновлении,
не возвращай defaults автоматически. Не редактируй установленный кэш пакета.

## Изменить и проверить

Составь минимальный diff нужного пользовательского слоя. Для замены существующего
предпочтения используй явное поручение; если его нет, сохрани значение, а при
блокирующем конфликте запроси решение по подготовленному diff. Не задавай общий
вопрос о разрешении установки повторно.

До правки сохрани закрытую резервную копию файла. Для пользовательского config.toml
предпочитай нативный config/batchWrite: передай только выбранные keyPath, value
и mergeStrategy="upsert" в edits, а также expectedVersion пользовательского слоя. upsert может
заменять существующий scalar; он не означает «добавить только отсутствующее».
Отбор отсутствующих и явно выбранных для замены ключей выполняй до вызова.
При конфликте версии заново прочитай
слои и пересчитай diff, не повторяй запись с пустым expectedVersion.

Этот RPC предназначен для пользовательского config.toml. Не направляй его на
проектный файл и не считай config/read подтверждением изменения текущего потока.
Если RPC недоступен, используй точечный редактор с сохранением остальных таблиц
и комментариев, проверкой исходной версии и синтаксиса. Не добавляй вторую таблицу
agents и не переписывай весь документ ради нескольких полей. Не редактируй
config.json, секреты или кэш плагина.

Проверь синтаксис TOML и доступную строгую проверку клиента, затем сопоставь
эффективные значения с ожидаемыми. Если проверка отвергла правку, восстанови
только собственное изменение, сохранив параллельные пользовательские правки.
Укажи настроенные и непроверенные значения отдельно. Изменение файла относится
к следующей сессии; текущая модель от этого не переключается.

Формат запроса закреплён в
[ConfigBatchWriteParams](https://github.com/openai/codex/blob/695961ee88a2c84c0919814a4345b94a2d10f3ca/codex-rs/app-server-protocol/schema/typescript/v2/ConfigBatchWriteParams.ts).
reloadUserConfig не обновляет model/reasoning текущей сессии; проверяй поддержку
RPC установленным клиентом, а не только наличие его описания в документации.
