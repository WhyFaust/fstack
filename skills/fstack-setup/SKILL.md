# Настроить профиль fstack

Это onboardingSkill плагина: нативный Setup и явный вызов навыка ведут сюда.
Запрос полного профиля разрешает обычную синхронизацию в этом же ходе.
Запрос проверки оставляет файлы без изменений. Для просмотра и точечной правки
настроек используй [диалог настройки](references/settings-ui.md); он не запускает
синхронизацию ролей и AGENTS.md.

## Найти источник и целевой профиль

Определи фактический `CODEX_HOME`, версию Codex, Python 3.11+ и включённый пакет.
Источник бери из пути текущего навыка или `installedPath` результата установки,
не из Git-клона или угаданной версии кэша. Корневые скрипты и профиль входят
в установленный пакет. Для устройства интеграции прочитай
[руководство Codex](../../docs/codex.md).

Поставляемые роли закрепляют `gpt-6.1-sol`: auditor и verifier используют `low`,
coder и allure_analyst `medium`, reviewer `high`. Пример настройки координатора
предлагает `gpt-6.1-sol` с `low`. Перед записью прочитай
[настройки и конфликты](references/configuration.md): проверь пользовательские
предпочтения, переопределения и миграцию старых ролей. Явное последующее решение
пользователя сохраняется; несовпадение покажи, не скрывай его defaults пакета.

## Выполнить dry-run, apply, dry-run

Запускай команды из найденного корня установленного пакета. `--home` добавляй
для явно выбранного целевого профиля; без него helper использует `CODEX_HOME`.

```text
python scripts/sync_profile.py
python scripts/sync_profile.py --apply
python scripts/sync_profile.py
```

После первого dry-run прочитай план и конфликты до `--apply`. Helper управляет
ролями, блоком глобального `AGENTS.md` и состоянием fstack; `config.toml` он
не меняет. Конфликт разрешай по справке конфигурации. Не применяй `--adopt`
как принудительную замену. Если разрешение на конкретную замену уже дано,
не запрашивай его повторно.

Для полного профиля сам внеси необходимые совместимые настройки по той же
справке, сохраняя прочие поля. Затем выполни `--apply`: helper пересчитает план
перед записью. Последний dry-run должен показать отсутствие изменений для
неизменного пакета. Показ команд или примера config не означает выполненную установку.

## Проверить итог

Проверь TOML ролей, состояние fstack, эффективные настройки и обнаружение ролей
доступными средствами клиента. `AGENTS.override.md`, выключенные агенты или
несовместимое переопределение означают частичную настройку. Новые файлы
применяются к новым сессиям; установка не меняет модель текущего чата.

Для проверки установки в отдельном временном профиле доступен
`scripts/check_installation.py`: нужны установленный Codex и PyYAML.
Он не меняет рабочий профиль и не запускает модельные задачи. Разбор файлов
не доказывает поведение агента; пробные модельные задачи без запроса не запускай.

Сопоставь нужных провайдеров с каталогом клиента. Отсутствующий Allure Analysis,
KISHKI, VaultGoblin, RTK или OpenAI Docs обозначь как ограничение зависимой задачи.
Не устанавливай их, не подключай аккаунты и не добавляй изменяющий профиль hook
для завершения Setup.

Верни версию пакета, целевой профиль, роли, фактические модели и reasoning,
результат повторного dry-run и путь резервной копии. Отдельно назови конфликты
и непроверенную доступность; полные файлы в ответ не включай.
