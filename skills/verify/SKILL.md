# Проверить фактический результат

## Вход и границы

До правок установи снимок, критерии и обязательные проверки. Для существенного
критерия укажи вход, условия, ожидаемый исход и признак отказа. Для малой правки
проверь затронутый сценарий; для исследования обоснуй ответ.

При изменении общего контракта, прав, данных или порядка операций проверь
потребителей, инварианты, отказы и восстановление; при существенном риске
примени [$fstack:impact](../impact/SKILL.md). Для порученной независимой оценки
дай свежему специалисту критерии, снимок и первичные данные без истории
и вердикта автора. Он сам читает доказательства; учти доступ и approvals.
Для ревью используй [$fstack:review](../review/SKILL.md), для прогона — [$fstack:test](../test/SKILL.md).

## Порядок работы

- Для дефекта сравни исходный отказ и успех после правки. При недоступном
  воспроизведении проверь связь правки с причиной и укажи предел.
- Для поведения пройди границу потребителя и существенный отказ. Для сохранённого
  контракта сравни версии на одинаковых входах.
- Для скорости сравни сопоставимые данные, объём и среду; укажи разброс.
- Для настроек проверь разбор и реального потребителя; для экспорта открой или
  отобрази итог. Для отчёта сверь первичные данные, покрытие, единицу подсчёта и попытки.

Бери ожидания из требования или независимого эталона. Сохрани силу проверок,
исключения и границу интеграции. Обоснуй изменение ожиданий. Используй разрешённые
изолированные данные. Для инварианта класса входов при необходимости генерируй
примеры, сохрани seed и сокращённый отказ. Для порядка переходов примени
[$fstack:model-check](../model-check/SKILL.md) и сверь с кодом.

Сначала покажи отказ регрессии по исходной причине. Уже зелёный тест не доказывает
исправление. Не подменяй изменённую функцию проверкой вызова её mock. Подбирай
фикстуру по условию отказа; простому результату не нужен крупный snapshot.
Если unit-тест обходит native-код или интеграцию, проверь доступную границу
приложения и обозначь остаток.

Переиспользуй CI, если совпадают критерий, head SHA, job, попытка, входы и среда,
а обязательные условия выполнены. После правки по diff, зависимостям, входам
и настройкам определи применимость результатов. Повтори затронутые и обязательные
проверки; отдельно порученный прогон выполни в указанной среде.

Читай первичный вывод, код выхода, ошибки, пропуски и существенные попытки;
для инструмента сначала определи ошибку и формат. Различай ожидание одобрения,
запуск и результат. При timeout записи сверь целевое состояние перед повтором.
Отмечай ограничения доступа; не передавай секреты.

## Проверка и результат

По критерию дай снимок, команду или действия, условия, ожидание, наблюдение
и ссылку на результат. Обоснуй перенос с другого снимка; при успешном повторе
сохрани первый отказ. Различай «пройдено», «не пройдено», «заблокировано»
и «не запускалось»; для пробела назови недостающую предпосылку или проверку.

Завершай при покрытых критериях, выполненных обязательных проверках, разрешённых
существенных замечаниях и ясных пределах подтверждения.
