# Выбрать навыки для поручения

## Вход и границы

Для простого ответа из имеющихся данных без специального процесса ответь сразу.
Не загружай route и verify только ради такого ответа. Если метод
уже однозначно задан поручением, переходи к нему напрямую. Прямой переход
сохраняет выбор предметных дополнений по этапу, затронутой области и риску.

## Порядок работы

### Выбрать основной метод

Прочитай требования, ограничения роли и инструкции проекта. Явно указанный
пользователем навык учитывай первым. По именам и описаниям текущего каталога
выбери основной метод под ближайший самостоятельный результат поручения.
Не требуй от пользователя имя навыка или отдельную команду для его выбора.
Учитывай цель, этап, область и риск, а не размер diff. Учитывай полный доступный
каталог клиента, включая специализированные навыки других плагинов и провайдеров.
Если разрешённых методов fstack нет в списке клиента, дополни его именами
и описаниями из [каталога установленного пакета](../../docs/skills.md)
по точному пути из поручения либо относительно текущего установленного навыка.
Весь каталог тел не загружай.

Когда подходят несколько методов, сравни обещанный результат каждого с
поручением по [каталогу](../../docs/skills.md). Различай исследование, изменение,
независимую оценку готового результата и выполнение нового прогона.
При существенных зависимостях упорядочи этапы по fstack:plan. При
существенном риске для потребителей общего контракта оцени последствия
по fstack:impact до реализации.
Для контракта внешнего API сначала проверь специализированный навык,
при недостаточном охвате используй fstack:docs.

### Проверить предметные границы

Сопоставь следующий шаг с фактическими входами и эффектами. Для каждого
существенного условия выбери метод, который изменит решение, проверку или
операцию. Одного навыка провайдера может быть достаточно для вызова API, но
повторы и конкуренция требуют отдельно установить гарантию записи.

| Условие | Подходящий метод |
| --- | --- |
| Язык, фреймворк или внешний API | Специализированный навык проекта, клиента или плагина. Для Python-контракта используй fstack:python. Для недостающего API-контракта используй fstack:docs. |
| Общий интерфейс и существующие потребители | fstack:impact, для перехода потребителей — fstack:migrate |
| Повтор, транзакция, конкуренция или порядок событий | fstack:state, для проверки свойства автомата — fstack:model-check |
| Временная среда, процесс или общий ресурс | fstack:resources |
| Инженерный выбор или интерфейс пользователя | fstack:design или fstack:ui по результату этапа |
| Сценарий приёмки, производительность или браузер | fstack:verify для критерия, fstack:test для фактического прогона, fstack:perf для измерения, доступный навык браузера для работы с UI |
| Доставка или новый провайдер | Навык площадки и fstack:watch-pr для сопровождения, fstack:merge для разрешённого слияния |

Перед изменением кода прочитай fstack:no-comments, перед шумной командой —
fstack:rtk. Для прежних решений подключённого проекта используй
fstack:memory. Текущий контракт и возможности инструмента проверь по источнику.

При продолжении плана или переходе к другой границе повтори этот выбор до
первой новой операции. Например, создание новой сущности и обратимое обновление
схемы могут требовать разных методов, даже если обе задачи делаются через один API.

### Загрузить выбранные инструкции

Открой только выбранные SKILL.md по ссылкам из доступного каталога. Для
методов fstack, скрытых клиентом, используй относительные ссылки установленного
пакета. Сверяй полное имя, избегай одноимённых личных копий и путей к старому
кэшу. Пересматривая выбор в том же контексте, используй уже прочитанный
неизменившийся текст. Сохраняй краткую ссылку на источник и версию
в текущем контексте или существующей точке продолжения; перечитывай при изменении
источника или утрате нужного контекста. При передаче работы укажи условие, по
которому понадобился дополнительный метод, чтобы исполнитель мог его применить.

## Проверка и результат

Если нужный навык, каталог пакета или инструмент недоступен, назови пробел и
выполни доступную часть поручения способом, сохраняющим его контракт. Установка
плагина и изменение профиля требуют отдельного поручения. Выбор методов не
включает faust-mode, не расширяет права роли и не разрешает делегирование.
При смене задачи пересмотри только затронутый выбор, сохраняя границы поручения.
