# Спланировать последовательность работы

Планируй существенные зависимости до правок. Возьми цель, критерии, полномочия
и проверенные входы. Для продолжения сверь ближайший незавершённый этап.

## Построить порядок этапов

1. Для каждого результата назови вход, зависимость, владельца и наблюдение
   готовности. Для стека укажи базу веток, порядок слияния и проверку каждого
   PR или MR по [примеру](references/stacked-pr.md).
2. Отметь предположения. Исследуй вопрос, который блокирует следующий этап.
   В плане допустим явный исследовательский шаг с искомым наблюдением.
3. Упорядочь контракт и потребителей с допустимым переходным состоянием
   по [$fstack:migrate](../migrate/SKILL.md). Существенный вариант выбери по
   [$fstack:design](../design/SKILL.md).
4. Для нативного Plan Mode или Goal открой [правила клиента](references/native-codex.md).
   В Plan отдай решённый план и дождись перехода. При разрешённой работе веди
   краткий порядок в инструменте клиента или чате. Запускай этапы по готовности
   входов и ресурсов, при делегировании применяй [$fstack:delegate](../delegate/SKILL.md).

## Критерии завершения

## Выполнить и обновить план

Прими этап по [$fstack:verify](../verify/SKILL.md). Координатор сверяет решение и
доказательства, автор или проверяющий читает полный diff своей области. При
смене входа обнови зависимые шаги и проверки, сохрани итоги и причины решений.
Цель завершай по её критерию. Для паузы используй [$fstack:checkpoint](../checkpoint/SKILL.md).

Передай порядок, условия готовности и открытые вопросы. Закончи на плане по
такому запросу. При порученной реализации продолжай по готовым входам.
