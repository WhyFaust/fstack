# План зависимых PR или MR

```text
main
├── A  Совместимое чтение двух форматов
│   └── B  Запись нового формата
└── C  Исправление отдельного диагностического инструмента
```

Порядок слияния A → B. Изменение C можно подготовить и слить независимо.

| Изменение | База и зависимость | Область | Наблюдение готовности |
| --- | --- | --- | --- |
| A | `main` | Чтение сохранённых данных | Читатель возвращает один результат для контрольной записи каждого формата. Запись остаётся в старом формате. |
| B | Ветка A после подтверждения её контракта | Запись и её потребители | Через штатный API записывается новый формат, созданная запись и старая контрольная запись читаются. |
| C | `main` | Диагностический CLI | CLI при недоступном источнике завершает работу с ожидаемым кодом и понятной ошибкой. |

Для рабочего плана добавь владельца, ограничения правок и способ прогона.
После слияния A сверь целевую ветку и diff B. При смене базы или head обнови
доказательства, которые зависят от новой ревизии.
