# Определить срок жизни ресурсов

Для каждого создаваемого объекта запиши владельца и момент освобождения:
временный файл, соединение, процесс, порт, браузер, тестовый пользователь,
запись БД или удалённый стенд. Отдели ресурс задачи от уже существующего ресурса
пользователя. Повторное использование допускается при известном состоянии.

После каждого успешного шага подготовки зарегистрируй соответствующую очистку.
Следующий шаг может не завершиться. Восстановление должно работать при неполном
setup, ошибке сценария и повторном запуске. Если освобождение одного ресурса не
удалось, освободи остальные независимые ресурсы. Сохрани первичную причину отказа
и отдельно отметь незавершённую очистку.

Для параллельных работников согласуй отдельные ключи, пути, данные и порты.
При общей VM или БД проверь владение независимо от локального worktree.
Постоянную общую фикстуру явно опиши вместе с правилами изменения.

Освобождай конкретный принадлежащий задаче объект по проверенному идентификатору.
Не завершай все процессы с одинаковым именем и не закрывай пользовательский
браузер. Если ответ создания потерян, сначала выясни исход по fstack:manage-state.

Проверь отказ в середине подготовки и ошибку teardown на затронутой границе.
Для Python и pytest используй fstack:python. Логи, вложения Allure и другие
решающие материалы сохраняй так, чтобы очистка временной среды их не удалила.
В результате перечисли освобождённое, оставшееся и владельца дальнейших действий.
