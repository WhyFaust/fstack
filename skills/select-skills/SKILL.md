# Выбрать навыки для поручения

Для простого ответа из имеющихся данных без специального процесса ответь сразу.
Не загружай select-skills и verify-result только ради такого ответа. Если метод
уже однозначно задан поручением, переходи к нему напрямую. Прямой переход
сохраняет выбор предметных дополнений по этапу, затронутой области и риску.

## Выбрать основной метод

Прочитай требования, ограничения роли и инструкции проекта. Явно указанный
пользователем навык учитывай первым. По именам и описаниям текущего каталога
выбери основной метод под ближайший самостоятельный результат поручения.
Учитывай цель, этап, область и риск, а не размер diff. Учитывай полный доступный
каталог клиента, включая специализированные навыки других плагинов и провайдеров;
примеры fstack ниже его не заменяют. Весь каталог тел не загружай.

Исследование поведения ведёт fstack:investigate-code, изменение поведения —
fstack:implement-change, наблюдаемый сбой — fstack:debug-failure, перестройку
без смены поведения — fstack:refactor-code, независимое ревью — fstack:review-change.
Выбери fstack:verify-result для оценки доказательств, fstack:verify-project
для выполнения сценария через UI, API, CLI или установку. Для поиска официального
контракта API сначала выбери применимый специализированный навык. Если он
не покрывает поиск контракта, используй fstack:find-docs. Для объяснения
поведения через историю используй fstack:trace-history.
fstack:design-change разрешает инженерную неопределённость перед реализацией;
fstack:design-ui прорабатывает пользовательский сценарий и визуальное решение.
Перед упорядочиванием существенных зависимых этапов используй fstack:plan-work.
При существенном риске для потребителей общего контракта используй
fstack:assess-impact для оценки без правок при исследовании или планировании.
Если поручена реализация, закончи оценку до её начала. Вопрос модели или интерфейса требует
отдельного дизайна, если его решение влияет на выполнение.
Выбор определяется вопросом, а не наличием подходящего ключевого слова в файле.

## Подключить предметные навыки

Для технической приёмки прочитай fstack:verify-result. Перед изменением кода прочитай
fstack:no-comments. Для затронутого Python-контракта используй fstack:python,
затем только нужные справки: типы, asyncio, автотесты или их ресурсы.
Для существенной модели, состояния, границы или миграции выбери подходящий
приём через fstack:engineering-principles. Эти дополнения не заменяют основной метод.

При переходе к новой предметной границе или провайдеру пересмотри выбор
по актуальным именам и описаниям. До первой операции, включая переход к CLI,
прочитай применимый специализированный навык и необходимый навык провайдера.
Для памяти подключённого проекта используй fstack:use-memory. Если ожидается
шумный вывод, до запуска команды прочитай fstack:use-rtk. Текущий контракт
проверяй по источнику, а доступ к инструменту по каталогу и фактическому вызову.

## Загрузить выбранные инструкции

Оригинальный SKILL.md открывай из актуального каталога клиента; не используй
пересказ координатора или путь к старой версии кэша. Предпочитай точное полное
имя fstack в каталоге, избегая одноимённых личных копий. Полный неизменившийся
текст в том же контексте повторно не читай: пересмотреть выбор не означает
заново загрузить уже прочитанное. Сохраняй краткую ссылку на источник и версию
в текущем контексте или существующей точке продолжения; перечитывай при изменении
источника или утрате нужного контекста. Справки открывай по ссылке для
конкретного вопроса; упоминание другого метода не требует автоматической цепочки.

Если нужного навыка или инструмента нет, назови пробел и используй допустимый
способ с тем же контрактом. Не устанавливай плагины и не меняй профиль ради
обычного поручения. Метод не расширяет права роли и не разрешает делегирование.
При смене задачи пересмотри только затронутый выбор, сохраняя границы поручения.
