# Проверка навыка

## Сверить черновик

Проверь применимые пункты по изменённым файлам и связанным ресурсам.
Для малой правки достаточно затронутых пунктов. При новом методе или
существенной смене поведения проследи рабочий путь целиком.

1. **Маршрут.** Типичный запрос и его перефразировка подходят под описание,
   а близкая чужая задача не запускает этот навык. Для нового навыка режим
   явного и автоматического вызова соответствует задаче. Для существующего
   режим сохраняется, если изменение не поручено.
2. **Результат.** По входам, шагам и выходу можно выполнить рабочий сценарий
   и проверить, что получен нужный артефакт или ответ.
3. **Предпосылки.** Указанные инструменты, команды и контракты существуют
   в целевой среде. Для недоступной предпосылки понятен допустимый следующий шаг.
4. **Полномочия и отказ.** Инструкции сохраняют область поручения. При ошибке
   или неизвестном исходе записи исполнитель знает, что проверить перед повтором.
5. **Пакет.** Структура соответствует [шаблону](template.md), локализации
   согласованы. Изменённые метаданные, пути и ресурсы согласованы и доступны
   после установки. Для переноса сверены происхождение и уведомления.
6. **Чтение.** Основной файл даёт нужный маршрут без лишних загрузок. Справки
   доступны напрямую и открываются по конкретному условию.
7. **Доказательства.** Для изменившегося обещания есть проверка, а для важных
   прежних гарантий — подтверждение сохранения. Выбери проверки по разделу ниже.

Для существенного замечания укажи важность, файл и строку, достижимый сценарий,
последствие и минимальное исправление. Вкусовые правки и пробелы проверки
отделяй от доказанных дефектов. После исправления повтори проверки изменившихся
условий, используй прежние результаты там, где их предпосылки сохранились.

## Выбрать проверку

Разделяй три утверждения. Выбирай проверки по тому, что изменилось.

1. **Навык доступен.** Запусти существующую проверку пакета. При изменении
   установки или обнаружения проверь имя и доступ к нужным ресурсам в целевом
   клиенте. Для fstack используй `bin/fstack check-package .` и при проверке
   обнаружения `bin/fstack check-installation` по правилам проекта.
2. **Клиент выбирает навык по запросу.** Используй запросы из сверки черновика.
   При разрешённом модельном прогоне в fstack подай перефразировку и близкий
   запрос в активном faust-mode. В свежем чате с выключенным режимом проверь
   прямой вызов метода и обычный запрос без имени. Запиши наблюдаемые открытия
   инструкций, справок и результат. Если клиент скрывает чтение, укажи это.
   Список доступных навыков подтверждает обнаружение; проверка маршрута требует
   наблюдения за выполнением запроса.
3. **Работа даёт нужный результат.** При существенной правке метода проверь
   фактический артефакт, допустимые побочные эффекты, обработку существенной
   ошибки и прежние гарантии. Условия приёмки выводи из задачи и контракта.

Пакетная проверка подтверждает структуру. Автовыбор и выигрыш в качестве или
затратах требуют отдельных наблюдений. При явно разрешённом сравнении держи
условия одинаковыми, используй прежнюю версию или выполнение без навыка как
исходный вариант и включай случаи, на которых описание не подгонялось.
Сохраняй результаты вне пакета по fstack:verify-result. Для заявленного
ускорения используй fstack:measure-performance.
