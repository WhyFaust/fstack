# Проверка навыка

Разделяй три утверждения. Выбирай проверки по тому, что изменилось.

1. **Навык доступен.** Запусти существующую проверку пакета. При изменении
   установки или обнаружения проверь имя и доступ к нужным ресурсам в целевом
   клиенте. Для fstack используй `scripts/check_package.py` и при проверке
   обнаружения `scripts/check_installation.py` по правилам проекта.
2. **Клиент выбирает навык по запросу.** Подготовь типичный запрос, его
   перефразировку без имени навыка и близкий запрос, который должен пойти
   по другому маршруту. Сверь с ними описание. Если модельные запуски входят
   в поручение, проверь автовыбор без явного имени навыка. Явный вызов
   проверяет исполнение маршрута только при фактическом запуске.
3. **Работа даёт нужный результат.** При существенной правке метода проверь
   фактический артефакт, допустимые побочные эффекты, обработку существенной
   ошибки и прежние гарантии. Условия приёмки выводи из задачи и контракта.

Пакетная проверка подтверждает структуру. Автовыбор и выигрыш в качестве или
затратах требуют отдельных наблюдений. При явно разрешённом сравнении держи
условия одинаковыми, используй прежнюю версию или выполнение без навыка как
исходный вариант и включай случаи, на которых описание не подгонялось.
Сохраняй результаты вне пакета по fstack:verify-result. Для заявленного
ускорения используй fstack:measure-performance.
