# Перестроить код, сохранив контракт

Прочитай verify-result из текущего каталога перед выбором исходных проверок
и изменением кода. Полный текст, уже находящийся в контексте, не загружай снова.
Для существенного решения о границах, состоянии или миграции используй
подходящий метод через engineering-principles.
При изменении кода применяй fstack:no-comments. Для уборки только подготовленного
diff используй fstack:simplify-change без расширения области на старую архитектуру.

Установи порученную область и конкретную причину перестройки. Более широкое
разбиение работы остаётся за координатором.

## Зафиксировать исходное поведение

Прочитай потребителей, тесты и соглашения проекта. Определи сохраняемые выходы,
побочные эффекты, ошибки, порядок, гарантии времени, публичный API и жизненный
цикл, где они существенны. Известный дефект отдели от контракта сохранения
поведения; не исправляй посторонние дефекты скрыто под рефакторингом.

Сохрани подходящую исходную проверку. Для узкого изменения достаточно имеющихся
тестов; для рискованного используй фиксацию фактического поведения, повтор
входных данных, сравнение старого и нового или представительный интеграционный
прогон. Снимок полезен, если выражает содержательный контракт.

## Уменьшить конкретную сложность

Выбери изменение по реальной цене чтения и сопровождения: переходам между
слоями, одновременно удерживаемым предположениям, неясному владению или
повторяющимся решениям. Локализуй состояние, сблизь связанное поведение и убери
посредников без ответственности.

Выделяй модули и типы для реальных границ, а не ради размера файла или шаблона.
Сохраняй полезную инкапсуляцию и намеренные ограничения, подходящие требованиям.
Документированный долг не всегда является дефектом.

## Мигрировать полностью

Найди затронутые вызовы, импорты, строковые ссылки, настройки, тесты, примеры
и документацию. Перед удалением публичного API учти внешних потребителей.
Совместимый переходный слой нужен только при реальном контракте миграции,
с владельцем и условием удаления; не оставляй вторую реализацию по привычке.

Делай связные проверяемые шаги. Не смешивай широкое переименование, изменение
поведения и заявление об ускорении без необходимости. Сохрани чужие правки
и согласуй общие интерфейсы.

## Показать сохранённый результат

Сравни результат с исходным через затронутую границу по verify-result.
Ожидания тестов выводи из согласованного поведения. Если скорость входит
в контракт, включи её в исходное измерение. Передай старое и новое распределение
ответственности, сохранённые контракты, мигрированных потребителей, практическую
пользу и ограничения. Дополнительную уборку оставь вне поручения.
