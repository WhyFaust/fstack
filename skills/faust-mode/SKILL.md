# Включить faust-mode

[Каталог · Координация](../../docs/skills.md#координация)

Команда `/faust-mode`, [$fstack:faust-mode](SKILL.md) или `$faust-mode`
в начале сообщения включает режим только в этом чате, `/faust-mode-off` там же
его выключает и подавляет автоматическое включение до следующей ручной команды
включения. Хук также включает координатор на отдельное сообщение основного
чата, если подтвердил выбранную глубину `ultra` для этого хода. Для временного
чата используй явный вызов. Цитата не включает навык. В обычном чате применяй
только явно вызванный навык. Соблюдай запрет пользователя на навыки или подагентов.

Если явный вызов пришёл во время работы, прочитай `SKILL.md` по пути из вызова
или из установленного пакета. Продолжи оставшуюся работу в режиме с ближайшего
действия, даже если на это сообщение не ответил хук. При `/faust-mode-off` в начале
сообщения сразу прекрати координацию по faust-mode, включая новые запуски.
За выбор между ходами отвечает хук. Если он не подтвердил команду во время
работы, предупреди пользователя, что для сохранения выбора команду нужно
повторить отдельным сообщением после этого хода.

На простой вопрос ответь сразу. До предметного действия выбери по
[route](../route/SKILL.md) метод и дополнения для текущего этапа. Используй список
из хука или [каталог](../../docs/skills.md), открой выбранные инструкции.
При смене этапа пересмотри выбор. Обратимые детали решай сам, при нехватке
полномочий запроси их и выполни независимую часть. При сбое установи причину
до распределения правок. Создавай подагентов для самостоятельных поручений,
которые можно выполнить независимо. Способ запуска, контекст и глубину выбери
по [delegate](../delegate/SKILL.md). Нативную цель
создавай по прямой просьбе по
[правилам клиента](../plan/SKILL.md#plan-и-goal-в-codex).

## Сопровождение GitLab MR

До первого чтения или записи по GitLab MR, включая публикацию ветки, открой
[$fstack:watch-pr](../watch-pr/SKILL.md). Определи точку остановки по поручению,
правилам проекта и полномочиям. Явно включённый faust-mode вместе с прямым
поручением опубликовать правку через GitLab MR задаёт полный разрешённый цикл
до Merged, если пользователь не ограничил его более ранней точкой. Соблюдай
порученные Draft, Ready, проверку статуса и передачу на личное ревью.
Автовключение на `ultra` даёт маршрут работы. Разрешение на записи определяй
по [merge](../merge/SKILL.md#установить-разрешение-и-готовность).

В `get_merge_request` передавай максимум одно значение `include` за вызов.
Перед оценкой готовности к слиянию или одобрением открой [merge](../merge/SKILL.md).
Передай ему исходное поручение, область разрешения и проверенный SHA. Сохрани
эти данные при ожидании и возобновлении. Веди MR через CI и очередь до
порученной точки или конкретной блокировки с указанием следующего действия и
его владельца. При отказе Guardian [останови серию](../watch-pr/SKILL.md#остановить-серию-записей-при-отказе).

Сверь результат с критериями, изменения и ответ проверь по [unslop](../unslop/SKILL.md).
При порученном разборе хода используй
[skill](../skill/SKILL.md#разобрать-завершённую-работу).
Сообщи результат, доказательства и существенные пробелы. Для PR/MR дай ссылку,
ревизию и CI, при блокировке назови недостающую предпосылку.
