# Включить faust-mode

## Вход и границы

Команда в начале сообщения `/faust-mode`, [$fstack:faust-mode](SKILL.md) или `$faust-mode` включает
процесс в текущем чате. Выполняй следующие запросы в этом режиме, пока
пользователь не начнёт сообщение с `/faust-mode-off`. В другом чате требуется
собственное включение. Состояние сообщает hook. Цитата, приложенный документ
и упоминание команды внутри обсуждения режим не включают. Явный запрет
пользователя использовать навыки или подагентов имеет приоритет над этим методом.

## Порядок работы

Координатор отвечает за цель, полномочия, решения и проверку результата.
Если достаточно известных данных, ответь без поиска и прогонов. Связную работу
веди сам. Для делегирования выбери самостоятельный результат и подготовь
короткое поручение с нужными инструкциями по [$fstack:delegate](../delegate/SKILL.md).

### Планирование и выполнение

Для задачи с зависимыми этапами подготовь план до первой правки или продолжи
с ближайшего незавершённого этапа по [$fstack:plan](../plan/SKILL.md). Учитывай
режим клиента и доступные инструменты плана. Разрешённые этапы выполняй сразу.

При продолжении нативной цели сверяй текущий результат с её условиями
завершения. Цель создавай по прямой просьбе пользователя через доступный
инструмент Codex. Порядок работы с режимами описан в
[правилах Plan и Goal](../plan/references/native-codex.md).

При сбое выбери [$fstack:debug](../debug/SKILL.md) до рекомендации
исправления. Сопоставь предлагаемое решение с исходной целью: какое условие
порождает отказ и какое наблюдение подтвердит его устранение. Качество выбранного
решения проверяй до распределения реализации между исполнителями.

Выбери основной метод по ближайшему результату. К очевидному методу переходи
прямо. Перед работой проверь предметные границы даже при известном основном
методе: язык и провайдер, общий контракт, состояние, миграция и способ проверки.
Выбери и прочитай инструкции, которые меняют следующий шаг. Например, метод
для написания API дополни методом для конкурентных записей, если запрос можно
повторить или выполнить одновременно. При неясном выборе используй
[$fstack:route](../route/SKILL.md).

При переходе к новой области, например браузеру или публикации MR, проверь
границы и выбери нужные методы. Используй уже прочитанные инструкции, пока они
применимы. Перед шумной командой прочитай
[$fstack:rtk](../rtk/SKILL.md), перед правкой кода — [$fstack:no-comments](../no-comments/SKILL.md); для Python добавь
[$fstack:python](../python/SKILL.md).

Память работает и в обычном чате. В подключённом проекте оцени итог хода и
рекомендации исполнителей по [$fstack:memory](../memory/SKILL.md). Читай память
вручную, если нужен контекст проекта, и сверяй выводы с текущими источниками.
По запросу разобрать прошедший ход и улучшить метод используй
[$fstack:skill](../skill/SKILL.md#разобрать-завершённую-работу).
В проекте GitLab, где изменения доставляются через MR, задача на реализацию
по умолчанию идёт от Draft до подтверждённого merge
по [$fstack:delegate](../delegate/SKILL.md). Такой маршрут включает публикацию и допустимый approve.
Явная граница пользователя или проекта определяет, где остановиться.

Если каталог клиента скрывает методы с выключенным неявным вызовом, используй
[каталог пакета](../../docs/skills.md) и относительные ссылки в нём.

## Проверка и результат

Ответь на языке пользователя в запрошенном формате. Начни с результата и
приведи основания, сохрани точные команды, условия и границы доказательств.
При техническом объяснении покажи, кто что сделал и к какому подтверждённому
следствию это привело. Раскрой новый термин через его роль. При передаче работы
назови текущее состояние, оставшийся шаг и обстоятельства, от которых он зависит.
