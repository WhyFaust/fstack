# Включить faust-mode

Команда `/faust-mode`, [$fstack:faust-mode](SKILL.md) или `$faust-mode` в начале
сообщения включает режим в этом чате. Отключает его `/faust-mode-off` в начале
сообщения. Состояние сообщает хук.
Каждый чат включает режим отдельно. Цитаты, документы и обсуждение команды
его не запускают. Явный запрет на навыки или подагентов имеет приоритет.

## Планирование и выполнение

- Держи цель, полномочия и критерии. Если неясную деталь можно решить обратимо,
  обозначь разумное допущение и продолжай. Если нужен выбор пользователя или
  дополнительные полномочия, задай вопрос и выполни независимую часть.
- Связную работу веди сам. Перед первым отдельным поручением открой
  [$fstack:delegate](../delegate/SKILL.md) и передай исполнителю вход в каталог
  через [worker.md](../delegate/worker.md).
- Если нужен план одного выбранного улучшения, открой [$fstack:scope](../scope/SKILL.md).
  Для порядка нескольких зависимых этапов используй [$fstack:plan](../plan/SKILL.md).
  Разрешённые этапы выполняй сразу. Нативную цель создавай по прямой просьбе.
  При продолжении сверяй её критерии по [правилам Plan и Goal](../plan/references/native-codex.md).
- При сбое начни с [$fstack:debug](../debug/SKILL.md). До распределения правок
  сверь причину, выбор решения и проверку устранения.
- До предметной работы выбери метод и дополнения по [$fstack:route](../route/SKILL.md).
  Используй [каталог установленного пакета](../../docs/skills.md) для полного
  списка fstack. При смене этапа или области повтори выбор. Для простого вопроса
  из имеющихся данных достаточно прямого ответа.
- Если пользователь просит запустить сценарий и сообщить, что произошло, начни
  с [$fstack:test](../test/SKILL.md). Если нужно оценить доказательства или выяснить,
  каких проверок хватает для приёмки, начни с [$fstack:verify](../verify/SKILL.md).
  Инструмент для прогона выбери, когда известен интерфейс продукта.
- Перед шумной командой прочитай [$fstack:rtk](../rtk/SKILL.md), перед правкой кода
  [$fstack:no-comments](../no-comments/SKILL.md), для Python также
  [$fstack:python](../python/SKILL.md). Используй уже прочитанные правила в их области.

В подключённом проекте оцени итог по [$fstack:memory](../memory/SKILL.md).
Хуки памяти действуют и в обычном чате. Для контекста читай применимые записи
и сверяй с источниками. По запросу разбора хода используй
[$fstack:skill](../skill/SKILL.md#разобрать-завершённую-работу).

## Сопровождение GitLab MR

В начале работы через MR зафиксируй конечное состояние (Draft, Ready или Merged).
Сверь поручение, правила проекта и полномочия. При отсутствии отдельной границы
веди полный разрешённый цикл до подтверждённого merge. Если проект требует
отдельного разрешения на merge, выбери Ready в пределах поручения и укажи,
чьё действие нужно для дальнейшего перехода.

До первой публикации ветки или изменения MR прочитай
[$fstack:watch-pr](../watch-pr/SKILL.md#полный-цикл-gitlab-mr). После создания Draft
или обновления head продолжай по этому методу до выбранного состояния.

## Завершение поручения

Сверь результат с критериями поручения. Выполни оставшиеся необходимые шаги
и проверки в пределах полномочий. Если завершению мешает блокировка, закончи
доступную работу и назови недостающую предпосылку.

Перед итогом по сопровождению MR перечитай GitLab. Сверь состояние, текущие
source и target SHA, применимые обязательные проверки, обсуждения и approvals.
Если следующий шаг разрешён и нужен для выбранного состояния, выполни его.

Ответь на языке пользователя в нужном формате. Начни с результата и его
последствий простыми словами. Поясняй незнакомые термины на месте. Углубляйся
по запросу или когда детали нужны для решения, проверки или воспроизведения.

Итог должен быть понятен без предыдущих сообщений. Укажи существенные
допущения, доказательства и пределы проверки. Для воспроизведения дай точные
команды и условия. Для PR или MR укажи ссылку, проверенную ревизию и статус CI.
При передаче назови следующий шаг и его зависимости.
Проверь текст по [$fstack:unslop](../unslop/SKILL.md).
