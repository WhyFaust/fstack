# Подготовить инженерное решение

## Вход и границы

Результат этого метода — решение, достаточное для реализации в пределах задачи.
Установи, какое наблюдаемое поведение нужно изменить, какие среды поддерживаются
и кто использует затронутый интерфейс. Прочитай ближайший работающий образец.
Проследи существующий поток и потребителей; сначала используй возможности
проекта и платформы. Зафиксируй вопрос, который мешает реализации, и останови
проектирование, когда выбранного решения достаточно для его разрешения.

## Порядок работы

Опиши данные и ответственность: что считается источником истины, какие состояния
допустимы, где поступают внешние значения, кто выполняет запись и освобождает
ресурс. Выбирай представление под нужные операции и срок жизни данных.

Для существенной неопределённости сравни реально возможные варианты по цене
изменения, совместимости, риску ошибки и проверяемости. Обычный выбор не требует
формального исследования альтернатив. Прототип нужен для конкретного вопроса,
который не решается чтением кода или документации. До прототипа укажи, какой
результат изменит выбор варианта. После проверки перенеси в решение найденное
ограничение и его последствия для реализации.

Проверяй вход на границе доверия. Внутри используй понятные предметные значения
и необходимые инварианты. Используй единую схему контракта. Статический тип не подтверждает,
что входное значение прошло проверку во время исполнения.

Проследи путь пользователя, включая ошибки и доступность. Для API учти реальных
клиентов, для UI — действия и наблюдаемый результат. Отделяй вычисление от I/O,
если это делает зависимости и проверку понятнее.

## Проверка и результат

В плане укажи выбранный вариант, причину, затронутые части, порядок внедрения
и доказательство готовности. Для конкуренции примени fstack:manage-state,
для перехода потребителей — fstack:migrate-contract. Следующий шаг определяется
действующим поручением: продолжай уже разрешённую реализацию либо передай решение.
