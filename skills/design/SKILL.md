# Подготовить инженерное решение

Назови поведение, среды, потребителей и вопрос, который мешает реализации.
Проследи поток по ближайшему рабочему образцу; сначала проверь возможности
проекта и платформы. Остановись, когда решения достаточно для реализации.

Назови источник истины, допустимые состояния, места внешнего входа, владельцев
записи и освобождения ресурсов. Подбери данные по операциям и времени жизни.
Проверяй внешний вход на границе доверия по единой схеме: статический тип не
заменяет проверку значения. Внутри используй предметные значения и инварианты.

Сравни реальные варианты для существенного выбора: цена, совместимость, отказы
и проверяемость. Для интерфейса покажи типичный вызов каждого варианта: вход,
порядок действий и состояния, которые должен знать потребитель. При равных гарантиях
выбирай ясного владельца и один прямой способ. Повторяющийся обход — повод проверить
границу; при подтверждённом дефекте пересмотри её и обнови проверки.

Прототипируй с разрешением вопрос, который не решает чтение. Заранее назови
результат, меняющий выбор; зафиксируй наблюдение и последствия. Оставленный
пользователю выбор верни с последствиями вариантов.

Проверь путь пользователя, ошибки и доступность: для API — реальных клиентов,
для UI — действия и результат. Отдели вычисление от I/O, если это упрощает проверку.

Передай вариант, причину, границы, порядок внедрения и критерий готовности.
Для конкуренции используй [$fstack:state](../state/SKILL.md), для перехода —
[$fstack:migrate](../migrate/SKILL.md). Продолжай реализацию, если она уже поручена.
