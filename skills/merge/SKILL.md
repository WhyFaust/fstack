# Выполнить разрешённое слияние

[Каталог · Ревью и доставка](../../docs/skills.md#ревью-и-доставка)

Цитата не включает навык. Вне faust-mode применяй только явно вызванные навыки.

## Установить разрешение и готовность

Сверь проект, PR/MR, target и разрешение на merge или auto-merge. Соблюдай
точку остановки и обещанное личное ревью. Полный цикл GitLab в faust-mode
включает публикацию, допустимый approval и merge. Проверь текущие head/base,
ревью, обсуждения, участников, approvals и обязательные проверки по
[watch-pr](../watch-pr/SKILL.md). После push повтори затронутые проверки.

В стеке GitHub проследи зависимости от целевой ветки и проверь полномочия
на весь эффект. Сливай готовые PR от основания до первого непроверенного
предшественника. После каждого слияния сверь target, новый diff и проверки
следующего PR. Независимую ветку оцени по её собственной базе.

## Одобрить текущую ревизию GitLab MR

Проверь учётную запись, автора, ограничения для участников коммитов и Code Owners.
Для самоодобрения нужны разрешение GitLab и отдельное явное согласие пользователя
одобрить эти MR от его имени. Сохрани область уже данного согласия. При отсутствии
запроси разрешение на конкретный MR и SHA либо дождись ревьюера.

В полном цикле после ревью поставь разрешённый approval даже при `approvals_required=0`.
Для MCP передай `method: approve` и полный `sha` в `save_merge_request_review`.
Для CLI используй [glab](../glab/SKILL.md). Подтверди запись и SHA через MR и
approvals. Используй действующий approval повторно. После push или сброса заново
проверь ревизию и правила. При неизвестном исходе перечитай до повтора.

При первом отказе Guardian [останови серию](../watch-pr/SKILL.md#остановить-серию-записей-при-отказе).
Назови препятствие и нужного ревьюера. Дождись обязательных одобрений.

## Выполнить слияние

В полном цикле до записи сообщи MR, SHA, target, pipeline и итог, участников,
approvals и ограничения. Делегат ждёт сигнала координатора. Действующее
разрешение позволяет продолжить. Для GitLab передай проверенный `sha`.
При разрешении на конкретную ревизию требуй проверки ожидаемого SHA для
каждого затронутого изменения, в том числе при auto-merge после push.
При смене условий перепроверь готовность и полномочия. Сохраняй защиты ветки.

## Подтвердить результат

Перечитай состояние всех затронутых PR/MR. Подтверди целевую ветку и принятый
коммит с учётом merge/squash/fast-forward. Для GitLab — `state=merged`. Дождись
фактического результата очереди или train. Перед повтором частичной операции
сверь исходы, текущие SHA оставшегося стека и полномочия.
