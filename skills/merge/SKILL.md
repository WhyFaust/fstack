# Выполнить разрешённое слияние

## Установить разрешение и готовность

Сверь PR/MR, проект, ветку и право на merge или auto-merge. Полный цикл
реализации через GitLab MR в faust-mode включает публикацию, допустимый
approval и merge. Явную точку остановки и обещанное личное ревью соблюдай.
Для GitLab CLI сначала проверь переход по [$fstack:glab](../glab/SKILL.md).

По [$fstack:watch-pr](../watch-pr/SKILL.md) установи текущие head/base, проверки,
обсуждения, approvals и участников. Сверь ревью на этот diff и повтори
затронутые проверки после push. До вывода о mergeability выполни доступный
approval, если GitLab его ждёт.

В стеке GitHub merge среднего PR захватывает нижние PR. Сверь полномочия
на все эффекты и начинай с нижнего готового изменения. Между шагами перечитывай
оставшийся стек. Смена target, rebase и правка чужой истории требуют полномочий.

## Одобрить текущую ревизию GitLab MR

Проверь учётную запись, approvals и право одобрить head. В полном цикле
поставь разрешённый approval после ревью даже при `approvals_required=0`.
Подтверждённый approval того же SHA используй повторно после сверки.

В MCP передай `method: approve` и полный `sha` в `save_merge_request_review`,
для CLI открой [$fstack:glab](../glab/SKILL.md). Подтверди запись и тот же SHA
по MR и approvals. При push или сбросе снова сверь и одобри актуальный SHA
при тех же полномочиях. При неизвестном исходе сначала перечитай.

Соблюдай правила самоодобрения, Code Owners и личного ревью. При недоступном
approval назови правило или ответ GitLab и нужного ревьюера. Дождись обязательных
одобрений. Если merge разрешён с текущими, сообщи их статус.

## Выполнить слияние

В полном цикле перед записью передай пользователю MR, проверенные SHA и
target, pipeline с итогом, участников, approvals и ограничения. Делегат
ждёт сигнала координатора после этой сводки. Действующее разрешение позволяет
продолжить сразу. При смене условий обнови проверку и сообщение.

Передай проверенный SHA, если forge поддерживает его. Для GitLab API используй
`sha`. При разрешении на конкретную ревизию требуй проверки ожидаемого SHA
для всех затронутых изменений и при auto-merge после push. Если гарантии нет,
остановись. При несовпадении снова проверь готовность и полномочия. Соблюдай
защиты ветки.

## Подтвердить результат

Перечитай затронутые PR/MR. Подтверди merge commit и целевую ветку, в GitLab
`state=merged`, проект и принятый коммит с учётом merge/squash/fast-forward.
Для оставшегося стека сверь base и head. Очередь и train наблюдай до фактического
merge или блокировки в пределах поручения.

При частичном отказе установи исход для каждого PR/MR. Перед повтором проверь
оставшиеся ревизии, полномочия и готовность.
