# Доказательства из работающего процесса

Читай эту справку при зависании, росте памяти, загрузке CPU, проблеме порядка
событий или отказе, который не объясняется доступным журналом. Сначала установи
процесс, ревизию, конфигурацию, нагрузку и интервал наблюдения.

Используй доступную штатную диагностику: stack dump для зависания, CPU profile
для нагрузки, снимки памяти для удерживаемых объектов, trace для порядка событий.
Выбирай артефакт под конкретный вопрос. Нагрузка от профилирования и содержимое
снимков могут быть существенными; соблюдай разрешения среды и правила данных.
Не меняй живой сервис и не ставь новую диагностику без полномочий на эти действия.

Сохрани исходный артефакт в разрешённом месте и выдели относящиеся к симптому
стеки, удерживающие ссылки, интервалы или события. Не помещай весь дамп в контекст.
Не публикуй секреты и пользовательские данные, попавшие в память или trace.

Сопоставь находку с исполняемой версией исходников и источником данных.
Горячая функция может быть следствием другой ошибки, а рост общего объёма памяти
сам по себе не доказывает утечку. Проверь конкурирующее объяснение наблюдением,
которое различает причины: контролируемым входом, повторным снимком или
изолированным воспроизведением при тех же существенных условиях.

Для проверки причины сохрани остальные условия и учитывай влияние инструментов.
Временные probes допускаются только в разрешённой области; убери свои изменения,
процессы и файлы по окончании. Не освобождай чужие ресурсы.

Передай симптом, условия, артефакт, локализованный механизм, место в исходниках
и степень подтверждения. Если поручена только диагностика, передай вывод без
исправления; иначе вернись к ограниченному исправлению и исходной проверке.
