# Python и автоматизированные проверки

Прочитай verify-result из текущего каталога перед изменением Python-кода
и выбором проверок, в том числе при прямом вызове этого навыка. Повторно читать
полный текст в том же контексте не нужно. Существенное решение об архитектуре
или состоянии оцени по подходящей справке engineering-principles.

Этот навык дополняет выбранный метод работы и инструкции репозитория,
не запускает отдельную реализацию или цепочку агентов.

## Соответствовать проекту

Определи поддерживаемую версию Python, менеджер зависимостей, активное окружение,
lock-файл и команды по проекту и фактическому runtime. Читай нужные записи lock,
а не весь файл по привычке. Используй настроенные форматтер, линтер, проверку
типов и runner; не предполагай Poetry, uv или pytest без основания.

Меняй зависимости и пересоздавай lock только по необходимости. Неопределённый
контракт зависимости сверяй с первичной документацией нужной версии. Сохраняй
диапазон Python и платформы проекта, включая Windows, если он поддерживается.

## Сохранять явные контракты

Соблюдай соглашения типизации изменяемых интерфейсов. Не прячь нерешённый
контракт за широким Any, подавлением типов, проглоченной ошибкой или вводящим
в заблуждение значением по умолчанию. Перед новой зависимостью проверь
подходящие средства стандартной библиотеки.

Делай владение состоянием и сроком жизни ресурса явными. Сохраняй причинные
исключения; ошибку очистки сообщай, не стирая исходный отказ. ExceptionGroup
и другие возможности конкретных версий допустимы только в диапазоне проекта.
Используй предметные типы и простую композицию там, где они решают реальную
задачу, без лишних классов, фабрик и общих каркасов.

## Владеть тестовыми ресурсами

При работе с фикстурами, pytest-xdist, SSH, базами, браузерами или общими стендами
читай нужные разделы [test-boundaries.md](references/test-boundaries.md).
Жизненный цикл, очистка и изоляция — часть проверяемого поведения.

Генеративные проверки свойств полезны для подходящих инвариантов; Hypothesis
не является обязательной зависимостью.

## Передать проверяемые данные

Запускай выбранные проверки в обнаруженном окружении. В доказательствах по
verify-result укажи существенные версии, условия параллелизма и изоляции,
а также состояние очистки ресурсов.
