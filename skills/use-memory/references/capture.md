# Подготовка записи памяти

В обычном чате вне Plan оцени, пригодится ли результат хода в следующих чатах. Сохраняй принятые или проверенные в работе решения, поправки к прежним
правилам и устойчивые предпочтения с понятной областью. Для предпочтения
опирайся на слова пользователя или повторившийся выбор. Укажи источник и
дату события, если они известны. Временно важный прогресс относится
к fstack:checkpoint-task, код и команды проекта хранятся в репозитории.
Исключи секреты, стенограммы, вывод инструментов и сведения, которые
пользователь просил забыть.

Запиши краткий вывод, условия его применения и основание доверять ему:
явный выбор пользователя или наблюдаемый результат проверки. Не подменяй
проверку объяснением, которое только выглядит правдоподобным. Сохраняй
полезные выводы как из успешной работы, так и из исправленных ошибок.
Дай записи заголовок с предметом решения и терминами проекта, по которым её
будут искать. Держи один связный вывод вместе с ограничениями; не склеивай
независимые темы и не теряй условия ради краткости. Новая сводка найденных
заметок без нового вывода не требует отдельной записи.
Не копируй доступное текущее состояние проекта; сохраняй то, что иначе
пришлось бы заново выяснять. Перед записью проверь близкие заметки через
поиск: совпадение смысла без нового знания требует `skip`, изменение правила
требует `supersedes`. Совпадение слов само по себе не доказывает дубликат.

В режиме `auto` сам выбери `remember` для обоснованной долговечной записи.
Подключение проекта в этом режиме даёт разрешение на сохранение без отдельной
просьбы. Полезный кандидат, который ещё нужно проверить, отправь через
`draft`. В режиме `inbox` записи ждут проверки. Если подходящего нового знания нет
или оно уже сохранено, выполни `stage --turn TOKEN --skip`.
Это подтверждение оценки, а не заметка в vault. Не придумывай знание ради
записи и не сохраняй одноразовую просьбу как устойчивое предпочтение.

В ходе с токеном хука вне Plan следуй [порядку записи из чата](commands.md#запись-из-чата)
с токеном текущего запроса. Для обычной поправки проекта используй
`stage --turn TOKEN --correction TITLE BODY`. Если пользователь прямо указал
«для всех проектов», сохрани предпочтение в общей области этого vault.
Разовый запрос и подробности отдельного проекта туда не переносятся. За ход подготовь одну
операцию. В Plan пропусти подготовку. Хук оболочки принимает операцию, а `Stop`
применяет её после завершения хода, включая продолжение после напоминания.
В подтверждённом обычном ходе `Stop` может один раз напомнить об оценке.
Если клиент не указал режим и агент пропустил оценку, ход завершится без
такого напоминания.
Используй последний токен из контекста хука: продолжение может принести новый
`UserPromptSubmit`. Повторное напоминание не требуется; при недоступном
инструменте или записи сообщи об ограничении и закончи основную задачу.
Хук не читает стенограмму и не извлекает знания из финального ответа.

При подтверждённом изменении того же правила укажи ID действующей записи
в `supersedes`, сформулируй полное новое правило с сохранёнными ограничениями
и добавь в `source` проверяемую ссылку на изменение, ревизию, тест или явно
названное решение пользователя. Проверь, что источник доступен и подтверждает
изменившуюся часть. Если есть только пересказ заметки, подтверждённого нового
правила ещё нет. Для полезной гипотезы используй `draft`.
Хранилище добавляет внутренние ссылки на проект и заменённую заметку.
Кандидаты в `inbox` исключены из обычного поиска. `approve` и `forget`
подавай только по явному поручению пользователя и с проверенным идентификатором
из текущего проекта.
При забывании текст удаляется, а короткая JSON-отметка рядом с заметками
защищает от возврата старой копии через синхронизацию.
