# Каталог навыков

Выбирай навык по результату, который нужен сейчас. Дополняющие навыки подключаются
для конкретной технологии или решения; они не заменяют основной метод.

| Навык | Когда применять | Что получить |
| --- | --- | --- |
| `investigate-code` | Объяснить существующий код, архитектуру или инцидент без правок | Достижимый путь, источники и неизвестные |
| `implement-change` | Добавить или изменить согласованное поведение | Полное изменение и проверки затронутого контракта |
| `debug-failure` | Есть конкретный сбой, регрессия или нестабильность | Причинное объяснение и проверенное исправление |
| `refactor-code` | Изменить структуру при сохранении поведения | Более ясное владение и подтверждение прежнего контракта |
| `review-change` | Проверить определённую ревизию или артефакт | Доказанные дефекты отдельно от советов и гипотез |
| `verify-result` | Выбрать достаточные проверки и оценить результат | Вывод, соответствующий силе доказательств |
| `engineering-principles` | Принять существенное решение об архитектуре или состоянии | Обоснованный выбор с учётом сложности и границ |
| `python-aqa` | Работать с Python, pytest, fixtures и параллельными ресурсами | Решение по нормам проекта с корректным cleanup |
| `find-docs` | Неизвестен контракт библиотеки или нужна её документация | Первичный источник для применимой версии |
| `glab` | Нужная операция GitLab недоступна через MCP | Точная CLI/API операция в пределах разрешённой задачи |
| `playwright-cli` | Проверить веб-интерфейс или Playwright-тест | Наблюдение через актуальный snapshot и нужные артефакты |
| `codex-config-evaluation` | Явно запрошено сравнение вариантов настройки | Контролируемое сравнение с обозначенным покрытием |

## Выбор без лишних переключений

«Почему так работает?» — исследование. «Добавь это поведение» — реализация.
«После изменения сломалось» — диагностика. «Упрости без изменения поведения» —
рефакторинг. «Найди дефекты в этом diff» — ревью.

Если работа переходит к другому результату, меняется основной метод. Загружать
все методы заранее не требуется. `verify-result` задаёт единый контракт
доказательств; повторять его текст в каждом навыке не нужно.

## Примеры

```text
Используй $fstack:debug-failure: найди причину сбоя этого запуска и исправь её.
Используй $fstack:refactor-code: упрости этот модуль, сохрани API и обработку ошибок.
Используй $fstack:find-docs: проверь контракт установленной версии библиотеки.
```

Описание навыка помогает автоматическому выбору. Явный вызов выбирает метод,
но не разрешает дополнительные записи, публикации или запуск сравнения моделей.
