# Установка и обновление

## Требования

Нужны Git и Codex с поддержкой Git marketplace и фоновых хуков. Поддерживаются
Linux x64 с glibc 2.35+, Windows x64, macOS Intel и Apple Silicon.
При первой загрузке каждой версии нужен `curl`. На Windows используются
системные `curl.exe` и Windows PowerShell. Python, Cargo и Rust на рабочем
устройстве не требуются.

## Через маркетплейс

Один источник подходит для всех поддерживаемых платформ:

```bash
codex plugin marketplace add WhyFaust/fstack --ref main
codex plugin add fstack@fstack
```

Зарегистрируй весь снимок ветки. Проверке пакета нужны файлы лицензий,
исходники в `tools/fstack` и файлы, на которые ссылается документация.

Одобри хуки fstack в настройках Codex и открой чат. Фоновый `SessionStart`
определяет ОС и архитектуру и читает версию манифеста и идентификатор
сборки из `launchers/runtime-id`. По ним он выбирает бинарник в GitHub
Release, проверяет SHA-256 скачанного файла и сохраняет его в
`<CODEX_HOME>/fstack/runtime/<версия>/<runtime-id>/<target>/`. Хуки памяти используют
локальную копию. На первом запуске память и команды режима становятся доступны
после загрузки. Если запрос пришёл раньше, хук покажет сообщение о пропуске.
После успешного `SessionStart` повтори команду режима или запрос, которому
требуется память. [Команды режима](faust-mode.md).

В существующем профиле этот же хук выполняет [миграцию прежних ролей](codex.md#миграция-прежних-ролей).
Для нового профиля достаточно установки и штатного доверия к хукам.
Результат подготовки виден в журнале хуков. Если релиз ещё публикуется
или сеть временно недоступна, следующий запуск чата повторяет подготовку.
Если до публикации этой версии в `main` вошёл следующий выпуск,
обнови marketplace до актуального снимка и открой новый чат. У версии,
которую успел заменить следующий выпуск, может не появиться бинарник.
Codex может запросить одобрение после изменения кода хука.

### Через платформенный архив

Для локальной установки скачай полный ZIP своей ОС из
[официальных выпусков](https://github.com/WhyFaust/fstack/releases).
Сверь файл `<имя-архива>.zip.sha256` того же выпуска и распакуй пакет в
постоянный каталог. Контрольная сумма проверяет целостность файла из выбранного
источника. Архив уже содержит платформенный бинарник.

```bash
codex plugin marketplace add /absolute/path/to/extracted-fstack
codex plugin add fstack@fstack
```

Одобри хуки и открой чат. Для смены существующей регистрации сохрани прежний
источник и порядок восстановления, описанный ниже.

### Установка из исходников для разработки

Собери бинарник по [руководству разработки](development.md#минимальные-проверки)
и помести в `bin/fstack` (`bin/fstack.exe` на Windows) внутри локального клона.
Зарегистрируй этот каталог как локальный marketplace. После изменения кода
собери бинарник заново, чтобы он соответствовал исходникам.

## Обновление

Клиент с поддержкой автообновления Git marketplace получает новый пакет
из `main` при запуске. Новый чат подготавливает бинарник этой версии.
Для немедленной диагностики доступны штатные команды:

```bash
codex plugin marketplace list --json
codex plugin marketplace upgrade fstack --json
codex plugin list --json
```

Сверь источник, версию и исходный `enabled` записи `fstack@fstack`.
Пустой `upgradedRoots` при отсутствии ошибок означает, что зарегистрированный
снимок уже получен. При таймауте проверь состояние регистрации и установленную
версию до повторной попытки.

### Сверить установленный снимок

Найди `installedPath` в ответе CLI или проверь
`<CODEX_HOME>/plugins/cache/fstack/fstack/<версия>`. Сравни манифест,
запускатели, хуки и изменённые ресурсы с подтверждённым источником.
Для локального архива или клона сверь также платформенный бинарник.
После подготовки бинарника перейди в `installedPath` и проверь состав пакета:

```bash
/bin/sh launchers/fstack.sh check-package .
```

```powershell
& .\launchers\fstack.ps1 check-package .
```

Если версия осталась прежней, проверь содержимое и отсутствие удалённых файлов.

### Переход с платформенной ветки

Если `fstack` уже зарегистрирован из официальной `marketplace/<target>`,
один раз переключи источник на `main`. Сохрани прежние URL, ref, версию и
`enabled`. Перед переключением проверь, что в `main` доступны запускатели
и опубликован GitHub Release версии манифеста.

Для включённого плагина:

```bash
codex plugin marketplace remove fstack
codex plugin marketplace add WhyFaust/fstack --ref main
codex plugin add fstack@fstack
codex plugin list --json
```

Проверь результат каждой команды. При сбое проверь фактическую регистрацию
и восстанови прежний источник. Для выключенного плагина пропусти
`plugin add` и проверь сохранение состояния отключения. При следующем
включении одобри новый хук, если Codex запросит доверие, и открой чат.
После перехода [миграция профиля](codex.md#миграция-прежних-ролей) сработает
при запуске.

### Обновление локального источника

Распакуй проверенный ZIP в новый каталог, сохрани прежний каталог и
переключи регистрацию. Для клона разработчика обнови исходники, пересобери
бинарник и проверь установленный снимок. Если версия осталась прежней,
включённый плагин можно переустановить через `codex plugin add fstack@fstack`.
У команды есть побочный эффект включения плагина, поэтому для выключенной
установки используй её при явном включении.

### Запускатель для диагностики

Если клиент не запускает фоновые хуки, бинарник можно подготовить из корня
проверенного пакета вручную:

```bash
/bin/sh launchers/fstack.sh --install-runtime
/bin/sh launchers/fstack.sh migrate-profile --apply
```

```powershell
& .\launchers\fstack.ps1 -InstallRuntime
& .\launchers\fstack.ps1 migrate-profile --apply
```

## Переход с личных копий

Проверь обнаружение установленных навыков. Если в личном каталоге навыков
остались одноимённые старые копии, перенеси их в резервную папку вне путей
обнаружения. В старых сценариях замени `python-aqa` на `python`,
а вызовы снятых ролей — на [поручения с подходящим навыком](codex.md#замена-явных-вызовов).

## Удаление

```bash
codex plugin remove fstack@fstack
```

Codex удаляет установленный пакет. Память проекта в Obsidian, локальные
привязки и резервные копии прежнего профиля доступны после удаления.
При необходимости отдельно удали регистрацию маркетплейса через
`codex plugin marketplace remove fstack`.
