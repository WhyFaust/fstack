# Установка и обновление

Установка профиля не включает процесс автоматически. Полный режим запускается
командой `/faust-mode`; [переход с прежних версий](faust-mode.md) требует
синхронизации профиля и нового чата.

## Требования

Нужны Codex с поддержкой repo marketplace и Git. Репозиторий WhyFaust/fstack
публичный. Совместимость конкретного клиента проверяется через
`bin/fstack check-installation --codex <исполняемый-файл>` после
[подготовки средств проверки](development.md#минимальные-проверки);
совместимость со всеми версиями не предполагается. Для полного Setup и памяти нужен нативный бинарник из пакета для платформы.
Python и Cargo на пользовательском устройстве не нужны. Готовые сборки предназначены
для Linux x64 с glibc 2.35+ (не Alpine), Windows x64 и macOS Intel/Apple Silicon.
CI проверяет Ubuntu 22.04, Windows и macOS 15. Windows-сборка использует
статический C runtime и встроенный SQLite, без отдельного redistributable.

GitHub CLI может настроить существующую авторизацию Git:

```bash
gh auth status
gh auth setup-git
```

Выполняй настройку только если Git ещё не имеет доступа. Токены не добавляются
в URL, манифест или файлы навыков.

## Через маркетплейс

Официальный Git marketplace публикуется в ветках с готовыми бинарниками.

| Платформа | Ветка |
| --- | --- |
| Windows x64 | `marketplace/x86_64-pc-windows-msvc` |
| Linux x64, glibc 2.35+ | `marketplace/x86_64-unknown-linux-gnu` |
| macOS Intel | `marketplace/x86_64-apple-darwin` |
| macOS Apple Silicon | `marketplace/aarch64-apple-darwin` |

Определи ОС и архитектуру и зарегистрируй соответствующую ветку. Пример
для Windows x64:

```bash
codex plugin marketplace add WhyFaust/fstack --ref marketplace/x86_64-pc-windows-msvc
codex plugin add fstack@fstack
codex plugin list --json
```

Проверь, что `fstack@fstack` установлен и включён, и запусти **Setup**.
Ветки `marketplace/*` обновляет release workflow. `main` и теги
исходников предназначены для разработки.

### Через платформенный архив

Если нужен локальный источник, возьми полный архив своей ОС и архитектуры
из [официальных выпусков](https://github.com/WhyFaust/fstack/releases).
Сверь SHA-256 по файлу `<имя-архива>.zip.sha256` того же выпуска и распакуй
архив в постоянный каталог вне рабочих проектов. Сборки не подписаны.
Контрольная сумма проверяет целостность и требует доверия к издателю.

```bash
codex plugin marketplace add /absolute/path/to/extracted-fstack
codex plugin add fstack@fstack
codex plugin list --json
```

Если marketplace `fstack` уже зарегистрирован, используй порядок смены
источника из [раздела обновления](#переход-с-ветки-исходников).

### Установка из исходников для разработки

Git-репозиторий содержит Rust-код, но не готовые бинарники. Клонируй его
в постоянный локальный каталог, собери бинарник по [руководству разработки](development.md)
и положи его в `bin/fstack` (`bin/fstack.exe` на Windows) внутри этого клона.
Затем зарегистрируй именно локальный каталог со сборкой:

```bash
codex plugin marketplace add /absolute/path/to/built-fstack-clone
codex plugin add fstack@fstack
codex plugin list --json
```

Регистрация удалённого Git-источника не переносит локально собранный бинарник.
Не используй её вместо локального каталога со сборкой. Для обычной установки
выбирай платформенную ветку или архив. Хук ничего не скачивает и не собирает.

В интерфейсе Codex плагин доступен в личном маркетплейсе **Faust stack**.
Пакет содержит небольшие навыки. Исполнители переходят прямо к однозначному
методу; `fstack:select-skills` читают при необходимости выбора.
Сравнение конфигураций запускается только по явному поручению.

### Настроить полный профиль одним действием

После установки выбери **Setup** у плагина. В fstack уже объявлен нативный
`onboardingSkill`, поэтому Setup запускает навык настройки; см.
[официальное описание](https://developers.openai.com/plugins/build/plugins#add-an-onboarding-skill).
Если интерфейс не показывает Setup, попроси `$fstack:fstack-setup` настроить
полный профиль fstack. Если установленный навык ещё не виден, начни новый чат.

Агент сам находит установленный пакет и целевой профиль, показывает краткий план,
устанавливает пять ролей, согласует настройки и проверяет результат.
Общий пользовательский `AGENTS.md` не устанавливается. При переходе со старого
профиля helper однократно удаляет прежний проверенный блок fstack по
[правилам миграции](codex.md#миграция-глобальных-инструкций).
Запрос полного профиля разрешает обычное выполнение этих шагов в том же ходе:
копировать файлы или отдельно повторять команды не требуется. Запрос только
проверки ничего не меняет. Реальный конфликт требует решения по конкретной правке.

Полный Setup устанавливает модели и effort из TOML ролей. Значения,
приоритеты и сохранение личных изменений описаны в
[контракте профиля](codex.md#модель-и-reasoning).
Существующий `config.toml`, авторизация, провайдеры и разрешения сохраняются;
применимые отсутствующие параметры согласуются точечно.
`fstack profile` управляет ролями и состоянием fstack, включая миграцию старого блока;
точечную правку `config.toml` выполняет Setup-агент. Недоступная проверка моделей,
выключенные агенты или конфликтующие роли отражаются в статусе.
Наличие `AGENTS.override.md` само по себе не мешает установке.

После завершения начни новую сессию и проверь наличие навыков `fstack:`.
Обнаружение файлов не доказывает исполнение ролей; модельные пробы Setup не запускает.
Подробности и резервный способ через PowerShell — в [руководстве Codex](codex.md),
распределение работы и модели — в [руководстве оркестрации](orchestration.md).

### Выбрать настройки в беседе

Тот же **Setup** или `$fstack:fstack-setup` принимает запрос «Покажи настройки
и помоги изменить reasoning и параллельность». Агент покажет текущие значения,
уточнит только неуказанный выбор и применит определяющие его поля.
Модель сохраняется, если не запрошено её изменение; запрос настроек не запускает
полную синхронизацию ролей или миграцию старого блока. Запрос «Проверь профиль fstack без изменения файлов»
заканчивается отчётом без записи.

Это диалог настройки глобального профиля Codex; изменения могут действовать
в других его чатах. Обычная установка не требует анкеты. Подробнее о стартовых
запросах и доступных вариантах выбора — в разделе
[«Настройка из интерфейса»](codex.md#настройка-из-интерфейса).

## Обновление

Для зарегистрированной платформенной ветки выполни штатное обновление
через `$fstack:fstack-update`. Эквивалентные ручные команды:

```bash
codex plugin marketplace upgrade fstack
codex plugin list --json
```

При получении новой ревизии Codex обновляет кэш установленного плагина и
сохраняет его `enabled`. Если клиент уже получил ревизию, `upgradedRoots`
может быть пустым. `plugin add` нужен для первичной установки или если
включённый плагин остался на старой версии. Эта команда включает плагин.
Проверь установленную версию и запусти **Setup**, чтобы согласовать профиль.

В клиентах со штатным обновлением Git marketplace запуск Codex может
автоматически получить новый снимок и обновить кэш плагина. Для немедленного
обновления используй команду выше. Согласование ролей выполняет Setup или
`fstack-update` по запросу. После миграции состояния на `schema: 2` обновление
не обращается к общему `AGENTS.md`.
[Реализация запуска в Codex CLI 0.157.1](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/core-plugins/src/manager.rs#L2773).
Синхронизация профиля выполняется по явному запросу и проверяет личные
изменения перед записью.

### Переход с ветки исходников

Найди Git-источник `WhyFaust/fstack` через `codex plugin marketplace list --json`.
Если JSON опускает ref, сверь `marketplaces.fstack.ref` в `config.toml`
и `ref_name` в `.codex-marketplace-install.json` корня marketplace.
Для регистрации без ref или с веткой `main` перейди на платформенную ветку один раз.
Сначала подтверди, что выбранная ветка уже опубликована в официальном
репозитории. Запомни прежний источник и ref для восстановления. Пример для
Windows x64:

```bash
git ls-remote --exit-code https://github.com/WhyFaust/fstack.git refs/heads/marketplace/x86_64-pc-windows-msvc
codex plugin marketplace remove fstack
codex plugin marketplace add WhyFaust/fstack --ref marketplace/x86_64-pc-windows-msvc
codex plugin marketplace upgrade fstack
codex plugin list --json
```

Каждая команда должна завершиться успешно, прежде чем выполнять следующую.
Если включённый плагин остался на прежней версии, выполни
`codex plugin add fstack@fstack` и повтори проверку. Для выключенного плагина
сохрани состояние включения и проверь кэш после штатного обновления клиента.
Если переключение не удалось, проверь фактическую регистрацию, восстанови
прежний источник и отложи синхронизацию профиля. Для смены источника с архива
используй тот же порядок с сохранением старого каталога.

### Обновление локального источника

Для установки из архива проверь новый ZIP той же платформы и распакуй
его в отдельный постоянный каталог. Сохрани старый каталог до проверки,
переключи регистрацию на новый каталог и установи пакет. Если установка
не удалась, верни прежнюю регистрацию до синхронизации профиля.
`marketplace upgrade` обновляет только Git-источники.

Вызови `$fstack:fstack-update` с запросом «Обнови fstack с сохранением моих
настроек». [Навык обновления](../skills/fstack-update/SKILL.md) проверяет
фактический клиент, профиль и источник, обновляет только marketplace fstack
и сверяет установленный снимок, сохраняя состояние включения плагина.
Из подтверждённого пакета навык сразу проверяет план синхронизации
профиля и применяет только нужные изменения. Если профиль уже согласован,
проверка плана завершает обновление.
Обычные совместимые шаги уже разрешены запросом обновления. Личные модели,
effort и прочие настройки не заменяются без поручения; конфликт профиля
даёт частичный результат с конкретной причиной. Фоновых проверок нет.

Для локального клона разработчика сначала обнови исходники:

```bash
git -C /absolute/path/to/built-fstack-clone pull --ff-only
```

Заново собери бинарник по [руководству разработки](development.md), замени
`bin/fstack` (`bin/fstack.exe` на Windows) в этом клоне, затем установи его:

```bash
codex plugin add fstack@fstack
```

Установка берёт пакет и бинарник из зарегистрированного локального каталога.
Новая версия определяется `version` в `.codex-plugin/plugin.json`.

После ручных команд снова запусти **Setup** или попроси `$fstack:fstack-setup` обновить полный
профиль. Агент возьмёт текущий установленный пакет, синхронизирует роли и правила,
сохранит личные настройки и проверит итог. После этого нужна новая сессия.
На другом устройстве повтори установку и Setup с доступом к GitHub.

Стабильные пути ролей не зависят от каталога версии кэша. Релиз содержит и навыки,
и роли. Обновление устанавливает пакет по версии манифеста. Входящие в него
навыки имеют собственные версии в `metadata.version` и обновляются вместе
с пакетом.

## Переход с 1.x на 2.0.0

В профиле для выпуска 2.0.0 роль `python_coder` заменена общим `coder`, который
подключает `fstack:python` по задаче. Добавлен `verifier` для проверок и первичных
артефактов. Тогда источником управляемого блока стал `profile/AGENTS.md`, прежний
`profile/links.md` был удалён. Теперь оба пути отсутствуют: правила координатора
находятся в `skills/faust-mode/SKILL.md` и включаются явно. Удаление источника
блока и переход состояния профиля на `schema: 2` являются несовместимыми
изменениями; [миграция](codex.md#миграция-глобальных-инструкций) удаляет только
прежний блок с подтверждённым владением.

После обновления пакета запусти Setup с запросом полного профиля. Он выполняет
обычную миграцию и проверку; вручную переносить файлы не требуется.

Неизменённая управляемая роль `python_coder` попадёт в приватную резервную копию
и будет удалена. Изменённая или отсутствующая управляемая роль вызовет конфликт
даже с `--adopt`. Неуправляемая копия останется на месте и появится в
`unmanaged_retired`; запланированные или выполненные удаления указаны в `removed`.

Если собственные сценарии используют `python_coder` или читают
`profile/links.md` или `profile/AGENTS.md`, укажи их при настройке. Роль теперь
называется `coder`; автоматическую установку глобального блока нужно убрать,
а процесс включать через `/faust-mode`.

## Обновление настроек ролей

После перехода с наследования модели на явные поля ролей повтори полный Setup.
Он обновит неизменённые управляемые TOML с приватной резервной копией.
Личные изменения потребуют решения по конкретному конфликту. Параметры
`spawn_agent` теперь согласуются с TOML роли, поскольку не перекрывают их.
Значения перечислены в [контракте профиля](codex.md#модель-и-reasoning).

Схема состояния профиля остаётся 1. Условия принятия прежнего состояния,
конфликты и восстановление описаны в [руководстве Codex](codex.md).

## Переход на Python

Это исторический переход на v1: общий навык `python` заменил `python-aqa`,
а старое публичное имя было удалено.
Если ещё используешь инструкции до v1, обнови пакет, повтори `$fstack:fstack-setup`
и открой новую сессию.

В своих инструкциях и сохранённых командах замени прежний вызов на
`$fstack:python`, а относительные пути `skills/python-aqa/` — на `skills/python/`.
Не правь установленный кэш. Личные копии сначала сохрани вне путей обнаружения.
Типизация и asyncio доступны в справках; автотесты и их ресурсы остаются
дополнительными справками и не обязательны для каждой Python-задачи.

## Если Git-обновление прерывается по таймауту

При неизвестном исходе прочитай `codex plugin marketplace list --json` и
`codex plugin list --json`. Сверь источник и выбранный ref, затем повтори
обновление, только если нужный снимок ещё не получен. Для среды без доступа
к GitHub доступен [локальный архив](#через-платформенный-архив).

## Удаление

```bash
codex plugin remove fstack@fstack
```

Команда удаляет установленный плагин и его запись в конфигурации Codex.
Отдельно синхронизированные роли и состояние fstack
сохраняются. В профиле до миграции `schema: 1` также может оставаться старый блок
`AGENTS.md`. Ссылки оставшихся ролей на навыки удалённого плагина перестают работать.
Если требуется удалить и профиль, это отдельное поручение с проверкой владения
файлами и сохранением пользовательских изменений. Подробности — в
[руководстве Codex](codex.md#удаление-и-применение-настроек).

## Переход с личных копий

Сначала проверь установленные файлы и обнаружение всех навыков. Затем перемести
старые одноимённые личные каталоги из `CODEX_HOME/skills` в резервную папку вне
путей обнаружения навыков. Сохрани их содержимое и дату переноса. Встроенную
`.system` и навыки других плагинов не перемещай.

Не оставляй активными две копии одного метода: это создаёт неоднозначный выбор.
Для восстановления удали только `fstack@fstack`, верни личные каталоги из копии
и начни новый чат. Удаление плагина не должно удалять исходный Git-репозиторий.

## Локальная разработка

```bash
codex plugin marketplace add /absolute/path/to/fstack
codex plugin add fstack@fstack
```

При смене источника сначала удали прежнюю запись командой
`codex plugin marketplace remove fstack`. Для разработки
используй отдельный `CODEX_HOME`, чтобы не менять рабочую установку. Подробности
проверки пакета — в [руководстве разработчика](development.md).

## Память и внешние компоненты

Память fstack подключается к выбранному vault Obsidian на каждом устройстве.
Запусти `$fstack:use-memory` для настройки проекта и одобри хуки Codex.
[Память и переход с Notion](memory.md).

Notion и RTK устанавливаются отдельно. Их назначение и границы описаны
в [руководстве интеграций](integrations.md).

## Нативный Setup и границы lifecycle

Codex поддерживает `extensions.com.openai.onboardingSkill`: кнопка Setup
запускает навык в беседе по действию пользователя. Это не автоматическое
исполнение установочного скрипта. В проверенном контракте манифеста нет
`install`, `postinstall` или `update` для запуска произвольной команды.
Нативные операции над пакетами выполняет Codex CLI, а роли и миграцию старого блока
согласует `bin/fstack profile` из выбранного пакета. Windows использует
`bin/fstack.exe profile`. Корень определяется рядом с бинарником; для явного
источника доступно `--package ROOT` перед подкомандой.

`SessionStart` и другие hooks относятся к сессии, не к установке. Они не
записывают профиль, не загружают исполняемые файлы и не запускают Cargo.
Codex требует отдельной проверки доверия hook; обновление вложенного кода
может потребовать повторного одобрения. Доверяй только проверенному пакету,
включая его бинарник: checksum из того же недоверенного источника не защищает
от подмены издателем. Установка через web не развёртывает исполняемые файлы
на устройстве. Автоматического выбора платформенного бинарника манифест
не предоставляет. Платформу выбирают при регистрации Git-ветки или получении архива.

Источники: [упаковка и Setup](https://developers.openai.com/plugins/build/plugins),
[события и доверие hooks](https://learn.chatgpt.com/docs/hooks),
[разбор манифеста Codex](https://github.com/openai/codex/blob/36e074a2fb365aa788886495c82e6ea612226cd9/codex-rs/core-plugins/src/manifest.rs).
В compatibility-манифесте `.codex-plugin/plugin.json` поле `hooks` находится
на верхнем уровне; `onboardingSkill` остаётся в расширении `com.openai`.

Архивы не следует считать подписанными, если выпуск явно не содержит
проверяемой подписи издателя. Предупреждения Gatekeeper, SmartScreen и других
средств защиты не обходятся автоматически; checksum не является подписью.
Если система блокирует запуск, остановись и сообщи об этом пользователю.
