# fstack в Codex

Codex загружает навыки и хуки из установленного плагина. Команда
`/faust-mode` включает процесс fstack в текущем чате. Подробности в
[руководстве режима](faust-mode.md).

## Делегирование

Координатор сравнивает доступные проектные, личные, встроенные роли и роли
плагинов по задаче и правам, затем передаёт исполнителю критерии и метод.
При отсутствии профильного специалиста для вопроса к коду подходит `explorer`, для изменения —
`worker`, для независимой проверки — свежий штатный агент общего назначения.
Если клиент предлагает обычный запуск без выбора типа, нужную ответственность
передают в самом поручении. [Порядок назначения](../skills/delegate-work/SKILL.md#назначить-владельца).

Модель и reasoning определяются клиентом, выбранной ролью и
пользовательской конфигурацией. Проектные и личные агенты остаются доступны
по правилам Codex. [Документация Codex о подагентах](https://developers.openai.com/codex/subagents).

## Миграция прежних ролей

После перехода на пакет из `main` одобренный фоновый хук запускает
однократную миграцию. Реестр владения находится в
`<CODEX_HOME>/fstack/profile.json`. Поддерживаются прежние схемы 1 и 2.

- Для каждого известного файла роли требуется запись в реестре и совпадение
  SHA-256 всех байтов. Подтверждённые копии удаляются.
- Изменённые роли, ссылки и файлы без записи о владении остаются на месте.
  Отсутствующий файл считается уже удалённым.
- Для схемы 1 прежний управляемый блок в `AGENTS.md` удаляется при совпадении
  единственной пары маркеров и SHA-256. Байты вокруг блока сохраняются.
  Изменённый блок остаётся в файле.
- `config.toml`, проектные роли, личные инструкции вне старого блока,
  `AGENTS.override.md` и память Obsidian сохраняются.

Перед изменениями создаётся приватная резервная копия в
`<CODEX_HOME>/fstack/backups/profile-migration-*/`. Она содержит реестр
владения, прежнее содержимое затронутых файлов и `manifest.json` с хешами.
Хук сообщает путь к копии и перечисляет сохранённые изменённые файлы.
После успеха старый реестр удаляется, а последующие запуски пропускают миграцию.
До первой правки хук записывает имя этой копии в общий с прежним помощником
файл блокировки `fstack/profile.lock`. Если процесс прервётся, следующий
запуск продолжит миграцию из той же копии.
Перед удалением или заменой файла хук перемещает его в подкаталог `moved/`
этой копии и повторно сверяет изъятые байты. При конфликте хук сохраняет
новую версию пользователя. При ошибке записи он восстанавливает собственные
изменения, пока пути свободны или содержат записанные им байты. Если на пути
уже появился другой файл, изъятая версия остаётся в резервной копии.

Для диагностики из корня установленного пакета запусти:

```bash
/bin/sh launchers/fstack.sh migrate-profile
```

```powershell
& .\launchers\fstack.ps1 migrate-profile
```

Параметр `--home PATH` выбирает другой профиль. Для ручного применения в среде
без фоновых хуков добавь `--apply`. Просмотр плана работает только на чтение.

Если нужно восстановить прежнюю установку, проверь манифест резервной копии
и восстанови подтверждённые копии вместе со старым реестром. Сначала
сопоставь каждый путь с его текущим содержимым, чтобы сохранить более новые
личные правки. Для работы с восстановленными ролями используй старый пакет.

### Замена явных вызовов

| Прежнее назначение | Как поручить задачу |
| --- | --- |
| `auditor` | Штатный агент с навыком `investigate-code`, `debug-failure` или `watch-pr` по результату задачи |
| `coder`, `python_coder` | Штатный агент с `implement-change` или `debug-failure`, при необходимости с `python` |
| `verifier`, `reviewer` | Свежий штатный агент с `verify-project` или `review-change` |
| `allure_analyst` | Агент с доступом к исходным результатам и навыком их анализа |

Заменяй собственные обращения к старым именам в инструкциях и сценариях.
Новый чат использует текущий каталог агентов и навыков.
