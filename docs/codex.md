# Профиль Codex: конфигурация, инструкции и роли

fstack поставляет навыки, пять исходных ролей и переносимые примеры профиля.
Плагин не заменяет настройки Codex при установке. Роли синхронизируются отдельной
явной командой; личные настройки и данные остаются на устройстве.

## Что где находится

| Слой | Источник fstack | Назначение |
| --- | --- | --- |
| Настройки клиента | [config.example.toml](../profile/config.example.toml) | Пример для `CODEX_HOME/config.toml` |
| Общие договорённости | [AGENTS.md](../profile/AGENTS.md) | Короткий шаблон глобальных инструкций |
| Связи с пакетом | [links.md](../profile/links.md) | Управляемый блок, добавляемый в глобальный `AGENTS.md` |
| Личные роли | [profile/agents/](../profile/agents/) | TOML для устойчивого каталога `CODEX_HOME/agents/` |
| Методы работы | [каталог навыков](skills.md) | Навыки установленного плагина, имена `fstack:...` |

`CODEX_HOME` по умолчанию — `~/.codex`. Для отдельного профиля задай переменную
среды или передай `--home` helper. Каталог `profile/` внутри плагина является
источником примеров и ролей; он сам не становится глобальным профилем.

## Что указать в config.toml

Объедини пример со своим `CODEX_HOME/config.toml`, сохранив нужные существующие
секции. Не копируй его поверх авторизации, MCP или настроек других плагинов.

```toml
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[agents]
enabled = true
max_concurrent_threads_per_session = 2
default_subagent_reasoning_effort = "medium"
```

Лимит относится к открытым дочерним чатам и не включает основной. Роли `auditor`
и `reviewer` явно задают `high`; остальные используют доступные значения родителя,
настройки `[agents]` и явного назначения по правилам клиента. Поле `model` не задано:
выбери модель, реально доступную в твоём аккаунте и среде. Этот пример не меняет
политики среды или организации и не расширяет разрешения дочерних агентов.

По [официальной документации конфигурации](https://learn.chatgpt.com/docs/config-file/config-basic)
CLI overrides имеют приоритет перед доверенными проектными `.codex/config.toml`,
выбранным профилем и пользовательским `config.toml`; применяются и управляемые
ограничения среды. Это отдельная система от текстовых инструкций `AGENTS.md`.

## Какой AGENTS.md использовать

[Шаблон](../profile/AGENTS.md) содержит общие методы, авторизацию, владение,
делегирование и доказательства. Прочитай его и перенеси подходящие договорённости
в свой глобальный файл, согласовав их с уже существующими правилами. Helper
никогда не заменяет глобальный файл этим шаблоном: он управляет только коротким
блоком связей.

В проектном `AGENTS.md` указывай сведения конкретного репозитория: команды,
поддерживаемые версии, контракты, локальную среду и ограничения общих ресурсов.
Не дублируй там весь глобальный шаблон или все тексты навыков.

[Обнаружение инструкций](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
начинается с `AGENTS.override.md` либо `AGENTS.md` в `CODEX_HOME`, затем добавляет
файлы от корня проекта к рабочему каталогу. Ближайшие инструкции уточняют предыдущие;
на одном уровне `AGENTS.override.md` выбирается раньше `AGENTS.md`.
Если глобальный override активен, управляемый блок в обычном `AGENTS.md` может
не попасть в контекст. Helper не изменяет override; согласуй его отдельно.

## Роли

| Роль | Назначение |
| --- | --- |
| `auditor` | Ограниченное исследование и аудит без правок |
| `coder` | Реализация вне специфичной Python-работы |
| `python_coder` | Python, AQA, зависимости и владение ресурсами |
| `reviewer` | Независимая проверка определённой ревизии |
| `allure_analyst` | Allure, попытки, группы отказов и решающие вложения |

Codex обнаруживает личные standalone TOML в `CODEX_HOME/agents/`, а проектные —
в `.codex/agents/`; см. [официальное руководство](https://learn.chatgpt.com/docs/agent-configuration/subagents).
Автоматическое подключение ролей из манифеста плагина здесь не используется.
В профиле нет обязательной последовательности ролей: выбирай исполнителя по
поручению. Для независимого ревью основной агент должен назначить свежий контекст,
например `fork_turns="none"`, когда это поддерживает инструмент.

Роли ссылаются на навыки fstack и применимые провайдеры из текущего каталога.
Allure Analysis, KISHKI, VaultGoblin и OpenAI Docs не копируются в fstack и не
устанавливаются helper. Отсутствие нужного провайдера обозначается в той задаче,
где он нужен, а не маскируется несуществующим инструментом.

## Установка и первое принятие

Установи плагин способом из [руководства установки](installation.md).
В PowerShell сохрани путь, возвращённый самим клиентом, и сначала посмотри план:

```powershell
$installedPlugin = codex plugin add fstack@fstack --json | ConvertFrom-Json
$profileSync = Join-Path $installedPlugin.installedPath 'scripts/sync_profile.py'
python $profileSync
python $profileSync --apply
```

Для helper нужен Python 3.11+; сторонних Python-пакетов ему не требуется.
`--home` выбирает целевой профиль вместо `CODEX_HOME` и значения по умолчанию.
Dry-run не создаёт файлов и не разрешает выполнение пробных агентных задач.

Если существующие роли отличаются от пакета и ещё не управляются fstack, обычный
запуск покажет конфликт. Сначала сравни файлы. Для осознанного первого принятия:

```powershell
python $profileSync --apply --adopt
```

Флаг `--adopt` работает только с `--apply`. Он не разрешает заменять вручную
изменённые уже управляемые роли. Все конфликты проверяются до записи; при конфликте
отдельные независимые роли не обновляются. Перед изменениями создаётся резервная
копия в `CODEX_HOME/fstack/backups/`, состояние хранится в `fstack/profile.json`.
Существующий глобальный `AGENTS.md` сохраняется, кроме собственного блока fstack.

## Обновление и восстановление

После установки новой версии плагина снова получи её `installedPath`, посмотри
план и выполни helper с `--apply`. Не запускай helper из старого каталога версии.
Повтор без изменений возвращает `unchanged` и не создаёт новую резервную копию.
Если в исходниках пакета изменилась роль, а локальная копия сохранила управляемый
хеш, helper обновит её и сохранит предыдущую. Ручная правка управляемого файла
или блока останавливает синхронизацию; сначала согласуй её с исходниками пакета.

Резервная копия содержит прежние файлы и список созданных путей. При восстановлении
согласуй роли, управляемый блок и `fstack/profile.json` как одно состояние; не
подменяй только хеш для подавления конфликта. Наличие `fstack/profile.lock`
означает занятую или прерванную синхронизацию. До ручного удаления lock убедись,
что указанный в нём процесс больше не выполняется.

Helper не меняет `config.toml`, авторизацию, hooks или MCP. Удаление плагина не
удаляет устойчивые роли. Если плагин удалён, ссылки ролей на его навыки перестают
быть доступными: восстанови плагин или отдельно пересмотри роли. Начни новый чат
после настройки; чтение TOML не доказывает поведение нового агента.
