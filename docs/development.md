# Разработка

## Среда

Python 3.12+ и зависимости нужны только для проверок. Сам плагин не устанавливает
Python-пакеты и не запускает сценарии при подключении.

```bash
python -m pip install -r requirements-dev.txt
python scripts/check_package.py
python -m unittest discover -s tests -q
python scripts/check_install.py
```

Установочный тест требует `codex` в PATH; другой executable можно указать через
`--codex`. Он создаёт временный профиль с пробелом в пути, регистрирует локальный
маркетплейс, устанавливает пакет и обращается к app-server. Модель, хуки и реальные
задачи не запускаются. CI выполняет оба вида проверок на Ubuntu и Windows.

## Изменить навык

Редактируй исходники в `skills/`. Сохраняй имя каталога и `name`, чтобы явные
вызовы продолжали работать. В `description` опиши реальное назначение и границу
выбора; детали отдельного режима выноси в справку, когда это сокращает загрузку
ненужных инструкций. Русские UI-метаданные находятся в `agents/openai.yaml`.

Изменение навыка не даёт новых прав на инструменты, пользовательские данные и
внешние записи. Поддерживаемые необязательные policy/dependency поля сохраняй.
Не добавляй выдуманные возможности или обязательный полный проход по всем методам.

## Подготовить версию

1. Внеси согласованное изменение и проверь затронутые контракты.
2. Повышай `version` манифеста: patch для исправления, minor для совместимого
   расширения, major для несовместимой смены имён или поведения.
3. Запусти проверки, просмотри diff и публикуй изменения через PR.
4. После включения в `main` обнови marketplace и установку командами из README.

Существующие GitHub- и CLI-команды должны соответствовать установленной версии.
Успех структуры и установки подтверждает упаковку; качество решений агента
проверяется отдельным экспериментом, только когда он запрошен.
