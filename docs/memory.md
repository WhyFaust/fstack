# Память проекта

## Подключение

Открой vault Obsidian, одобри хуки fstack в Codex и начни чат в рабочей папке.
Хук создаст область проекта. Worktree одного репозитория используют общую область.
Если vault несколько, выбери его через `memory vault --set PATH`. Для ручного
подключения или восстановления выполни `memory init --vault PATH --repo PATH --project NAME --mode auto`.
Состояние профиля хранится вне Git-деревьев.

Из рабочей папки запусти команду своей платформы. `FSTACK_ROOT` указывает на
установленный пакет.

```bash
/bin/sh "$FSTACK_ROOT/launchers/fstack.sh" memory status
```

```powershell
& "$env:FSTACK_ROOT/launchers/fstack.ps1" memory status
```

Сверь проект и vault. Записи доступны в `Codex Memory/Home.md`, через
`memory search "запрос"` и `memory show ID`.

## Запись и поиск

В режиме `auto` подтверждённые решения и поправки сохраняются в проект,
кандидаты попадают в Inbox. В `inbox` все новые записи проходят ручную проверку.
Для общих предпочтений между проектами одного vault нужно явное указание.

Хуки связывают запись с ходом. В `memory diagnostics` проверь фазу операции:

| Фаза | Что произошло |
| --- | --- |
| `stage` | `PostToolUse` принял операцию. Ответ команды `{"staged": true}` сам по себе подтверждает только проверку аргументов и токена. |
| `applied` | `Stop` или `SubagentStop` применил запись. |
| `skipped` | Ход завершён без записи, в том числе при явном `--skip`. |
| `cancelled` | Прерывание отменило очередь. |
| `failure` | Запись не удалась. Проверь доступность vault и описание ошибки. |

До первой операции фаза может быть пустой. Plan пропускает запись. После сбоя хранилища
неотменённая операция может примениться в следующем обычном ходе этого чата.
Для поручения Codex или подагента хук запрашивает `memory report` при завершении
и сверяет происхождение хода по журналу. При проблеме проверь доверие к хукам,
`memory status` и `memory diagnostics`. [Команды агента и порядок записи](../skills/memory/SKILL.md).

## Заметки и представления Obsidian

В заметке можно менять текст и свойства `tags`, `aliases`, `cssclasses`
(строка или список YAML). Оставляй служебные поля и имя с ID под управлением
runtime. Для внутренней ссылки используй `[[путь/заметки|Название]]`.

Страница проекта фильтрует записи по области. `Library.base` показывает весь
vault. Inbox выводит старые кандидаты первыми, история — новые подтверждения.
В «Сохранённых» видны также заменённые записи. Если запись пропала из поиска,
проверь её через `show` и исправь повреждённый или слишком большой текст в Obsidian.

Для проверки представлений открой Obsidian и используй его штатный CLI:

```text
obsidian vault="Проверочный vault" base:query path="Codex Memory/Library.base" view="Сохранённые" format=paths
obsidian vault="Проверочный vault" backlinks path="Codex Memory/Projects/pilot/pilot.md" format=json
```

Сверь результат и отдельно открой встроенный Inbox проекта, чтобы проверить фильтр.

## Несколько устройств и отключение

Синхронизируй всю папку `Codex Memory`, включая JSON с отметками об удалении,
Bases и Canvas. В Obsidian Sync включи «Sync all other types» на каждом устройстве
и перезапусти Obsidian. [Настройки синхронизации](https://obsidian.md/help/sync/settings).

Выполни `memory init` с локальными путями и одним именем проекта на всех устройствах.
Перед изменением с другого устройства дождись синхронизации. `memory disable`
выключает автоподключение на текущем устройстве до следующего явного `init`.
