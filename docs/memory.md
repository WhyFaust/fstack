# Память fstack в Obsidian

Автоматический поиск и оценка памяти работают в чате после включения
`/faust-mode`. Каждый ход получает собственный токен. Команда
`/faust-mode-off` прекращает автоматическую работу с памятью в этом чате.
Ручные команды памяти доступны по явному поручению.

В полном процессе один назначенный исполнитель проверяет доступность памяти,
читает контекст по конкретному вопросу и готовит обоснованный кандидат с проверкой
дубликатов. Главный агент принимает вывод и выполняет pack/stage. Чтение навыка
и status не подтверждают сохранение. Без токена хука автоматическая операция
недоступна: требуется проверка установки, одобрения событий и режима.

`$fstack:use-memory` хранит долговечные записи в Markdown. На каждый
проект заводится своя область внутри `Codex Memory` в выбранном vault.
Obsidian показывает решения, поправки, предпочтения и кандидатов. Codex
использует память из рабочей папки подключённого проекта.

## Подключение

Нужны локальный Codex с поддержкой хуков плагинов, готовый пакет fstack
для своей платформы и существующий vault Obsidian. Python, Rust и Cargo
пользователю устанавливать не нужно: память работает через включённый
в пакет `bin/fstack` (`bin/fstack.exe` на Windows). На Windows хуки используют
PowerShell. Git нужен для общей привязки нескольких worktree.

Версия навыка `1.1.1` исправляет прежнюю завышенную нумерацию. Это не сброс
хранилища: существующие привязки, ID и заметки сохраняются. Переход на
нативную реализацию не требует повторного подключения или удаления данных.
Прежний файл `python-executable` больше не используется.

1. В новом чате попроси `$fstack:use-memory` подключить выбранный vault
   и рабочую папку. Выбери короткий идентификатор проекта латиницей.
2. Открой `Codex Memory/Home.md` в Obsidian. На главной есть ссылки на
   карту Canvas, таблицу и шаблоны. Список проектов и таблица записей работают
   через Bases. Canvas и Bases открываются одноимёнными основными плагинами Obsidian.
3. Проверь хуки fstack в **Settings → Hooks** в Codex Desktop или через
   `/hooks` в CLI. Одобри события `SessionStart`, `UserPromptSubmit`,
   `PostToolUse` и `Stop`, затем открой чат в подключённом проекте.
4. Выполни задачу через `/faust-mode`, в которой появится долговечное решение или поправка.
   Проверь сохранённую запись в Obsidian. Открой новый чат в том же проекте
   или его worktree и спроси о решении.

Команды ручной настройки и проверки описаны в [справке навыка](../skills/use-memory/references/commands.md).
После обновления изменённые хуки могут снова потребовать подтверждения.
[Документация Codex](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks).

## Как проходит ход

| Событие | Действие |
| --- | --- |
| `SessionStart` | Не добавляет контекст и не читает vault. |
| `UserPromptSubmit` | Переключает faust-mode по явной команде и при включённом режиме подбирает до трёх записей проекта для очередного хода. При ошибке поиска предупреждает, не прерывая основную задачу. Агент читает нужные заметки через CLI и отбирает новую долговечную информацию по результату хода. |
| `PostToolUse` | Принимает подготовленную операцию из аргументов отдельной команды `stage`. Данные хранятся в локальном профиле Codex. |
| `Stop` | Применяет подготовленную операцию или подтверждение отсутствия новых знаний. Если оценка пропущена, один раз возвращает ход для проверки памяти. При ошибке памяти Codex может завершить обычную задачу. |

В режиме по умолчанию `auto` Codex сам сохраняет обоснованные решения,
поправки и предпочтения из текущей работы без команды "запомни". Долговечный
кандидат, которому нужна проверка, попадает в `Inbox`. Режим `inbox`
предназначен для ручной проверки всех записей. Операции `approve` и `forget`
требуют явного поручения. Если новых подходящих знаний нет или они уже
сохранены, агент передаёт `skip`: это подтверждение оценки без текста,
которое не создаёт заметку. Отсутствие `stage` не считается такой оценкой.
`Stop` просит закончить проверку один раз; повторное продолжение не блокируется.
Операция, подготовленная после напоминания, применяется на следующем `Stop`.
Продолжение может вызвать новый `UserPromptSubmit`, поэтому нужен последний
выданный токен. Хук не читает историю чатов и не делает запись из финального
ответа сам. Он проверяет прохождение протокола, а обоснованность знания
оценивает агент. Доставка событий зависит от включённых и одобренных хуков
клиента; отсутствие новых заметок само по себе не доказывает поломку.
[Контракт продолжения Stop](https://learn.chatgpt.com/docs/hooks#stop).

В Plan агент пропускает запись и `skip`. Хук дополнительно
проверяет режим, когда клиент передаёт его в событии.

Токен подготовки связан с запросом, рабочей папкой и действующей привязкой.
Если пользователь отправил новый запрос в ходе выполнения, прежняя операция
отменяется. При ошибке фиксации отмены хук останавливает новый запрос и
показывает причину. Подготовленные операции хранятся в локальной очереди
`CODEX_HOME/fstack/memory` вне рабочих деревьев. После применения текст
удаляется. Хуки работают с краткой записью из текущего хода и идентификаторами.
Источник может содержать проверяемую ссылку, а автоматические записи хранят
идентификаторы чата и хода.

## Хранилище и Sync

```text
Codex Memory/
  Home.md
  Projects.md
  Memory.canvas
  Library.base
  Templates/
  Projects/<project>/
    <project>.md
    Records/
```

Текст, ссылки и статус записи хранятся в одной заметке в `Records`.
Library показывает заметку с `fstack_status: "approved"` в "Сохранённых",
а остальные кандидаты попадают в Inbox. Подтверждение обновляет свойства
той же заметки. На странице `Projects` можно открыть любой подключённый проект.
Именованная страница проекта связывает `Projects` с его записями в графе и
показывает его Inbox и сохранённые заметки. Свойство `supersedes_link` связывает
запись с её предшественником при замене. [Граф Obsidian](https://obsidian.md/help/plugins/graph).

Локальные привязки и очередь
лежат в `CODEX_HOME/fstack/memory`. Поиск строит локальный
индекс из Markdown текущего проекта. Изменения заметок видны при следующем
поиске. Встроенный SQLite с FTS5 обеспечивает полнотекстовое ранжирование
без установки отдельного сервера или библиотеки.

Поиск возвращает ограниченную подборку полных записей. Агент проверяет их
смысл, условия и актуальность перед ответом; позиция в выдаче не подтверждает
достоверность. При пустой или шумной выдаче он уточняет термины, а затем
обращается к текущим источникам, не загружая весь vault. Подробности доступны
в [порядке поиска](../skills/use-memory/references/retrieval.md).
Ошибка поиска не равна пустой выдаче: предупреждение хука не содержит текстов
заметок и сырых ошибок. Агент проверяет нужный запрос отдельным `search`;
при повторном отказе продолжает по текущим источникам без самовольного ремонта
или удаления записей. Поле предупреждения поддерживается
[контрактом хуков Codex](https://learn.chatgpt.com/docs/hooks#common-output-fields).

Эмбеддингов и векторного индекса в текущем runtime нет. Уменьшение `--limit`
сокращает выдачу, но не объём FTS5-индекса, который строится при каждом поиске.
Бинарная квантизация возможна только в отдельно реализованном векторном слое;
она не сжимает Markdown или контекст модели. Условия такой реализации описаны
в [справке навыка](../skills/use-memory/references/vector-retrieval.md).

На следующем устройстве дождись появления папки в Obsidian и повтори
`init` с путями этого устройства и тем же `--project`. Синхронизация
`Codex Memory` должна включать Markdown, JSON, Bases и Canvas. В Obsidian
Sync для дополнительных форматов используется параметр "Sync all other types".
Поиск и запись работают после локального подключения проекта.
[Настройки Obsidian Sync](https://obsidian.md/help/sync/settings).

Одинаковое содержимое получает одинаковый идентификатор. Повторная запись
сохраняет существующий файл с ручными правками. Для изменения смысла сохрани
новую запись со ссылкой `supersedes` на прежнюю. На одном устройстве операции
одного проекта последовательно применяются под локальной блокировкой.
`forget` удаляет заметку и оставляет в `Records` служебный файл
`<id>-forgotten.json` с ID. Для подтверждённой записи отметка хранит ID
предшественника или `null`, если предшественника не было. Library и подбор
контекста используют отметку, чтобы скрыть старую копию записи. При обычных
настройках Obsidian JSON-файл скрыт в проводнике и графе.
В Obsidian 1.15 при поздней доставке отметки переоткрой Library, чтобы
пересчитать открытое представление.
При прерывании `forget` повтор с тем же ID завершает локальную очистку.
Статус подтверждения синхронизируется вместе с заметкой. Перед её
подтверждением или удалением на другом устройстве дождись Sync.
Одновременные правки подчиняются правилам конфликтов Obsidian. Старые копии
из истории Sync и резервных копий управляются отдельно. [Разрешение конфликтов](https://obsidian.md/help/sync/troubleshoot#Conflict+resolution).

`disable` снимает привязку текущего проекта на устройстве. В Obsidian
можно по-прежнему открывать сохранённые записи. При неполной или повреждённой
подборке проверь `status`, синхронизацию и наличие `Home.md` с исходным свойством
`fstack_memory_home`. Повторный `init` дополняет отсутствующие представления
и обновляет стандартные фильтры статуса в Library.

## Переход с прежнего формата

Каталоги `Approved`, `Forgotten` и страницы `Projects/<project>/Project.md`
читаются при переходе с прежних версий.
Для переноса сначала обнови все устройства, на которых Codex использует
этот vault. Затем выполни обе фазы в порядке из
[справки навыка](../skills/use-memory/references/commands.md#переход-с-прежнего-формата).
Перенос сохраняет путь, ID и текст каждой записи. Именованная страница
остаётся в том же каталоге, поэтому её относительные ссылки продолжают
работать. Для проекта с именем `project` используется `Project.md`, чтобы
избежать двух имён одного файла на устройствах с разными файловыми системами.
При несовпадении файлов или неполной доставке исходники остаются для
проверки и повторного переноса.

Когда файл Library доступен для обновления, fstack заменяет известные
выражения статуса с сохранением настроек таблицы. Хранилище работает
независимо от настроек Library. Для своих фильтров добавь условие
`note.fstack_status == "approved"` к условию подтверждения. Для Inbox
используй отрицание условия подтверждения. В общем фильтре проверь
отсутствие новой JSON-отметки выражением
`file(file.folder + "/" + file.basename + "-forgotten.json") == null`.

## Переход с Notion

Новый контракт `use-memory` начинает с записей, подготовленных после явного
подключения Obsidian. Выбери vault, подключи проект и проверь сохранение одной
новой записи. Если в личных инструкциях выбран другой источник общей памяти,
согласуй с владельцем их назначение и обнови этот выбор отдельно. Настройки
документов и навыков Notion относятся к его [собственной интеграции](integrations.md).
