# Примеры работы

Эти запросы можно использовать в своих проектах. Ожидаемый результат описывает
критерий приёмки. Для сравнения сохрани конкретные входы и ревизии по
[протоколу экспериментов](evaluations.md).

## Сбой или медленная джоба

```text
/faust-mode Разберись, почему публикация отчёта занимает несколько часов
и не доходит до конца. Лог: <путь>. Исходники: <репозиторий и ревизия>.
Предложи варианты исправления и способы проверки.
```

Нужны границы фаз, доказанная причина задержки и связь решения с этой причиной.
Если публикация создаёт сотни тысяч маленьких объектов, проверь происхождение
объёма и контракт чтения отчёта. Повышение таймаута не подтверждает устранение
причины. Способ хранения выбирают после чтения потребителей, а не по этому примеру.

## Реализация и независимая проверка

```text
/faust-mode Реализуй <поведение> в <компоненте>.
Потребители: <ссылки>. Сохрани совместимость с <формат или сценарий>.
Критерии: <наблюдаемые исходы>.
```

Результат включает код, затронутых потребителей и проверки. Связную задачу
координатор может выполнить сам. Независимый проверяющий получает конкретную
ревизию и исходные требования. Повторять всё исследование без нового вопроса не нужно.

## Выбор моделей

```text
/faust-mode Подготовь два независимых материала к ревью пакета.
Первому исполнителю поручи собрать версии навыков из YAML и проверить ссылки
каталога. Второму поручи проверить совместимость изменения <diff> с потребителями.
Правки не нужны. Сведи результаты и ограничения.
```

Проверяют параметры реальных запусков и доступные метаданные клиента.
Для извлечения фактов достаточно быстрой модели, для спорного контракта нужна
более сильная. Самоотчёт о модели недостаточен. Если клиент не позволяет выбрать
модель, это ограничение должно попасть в результат.

## Самостоятельный прогон runtime

```bash
python tools/fstack/benchmarks/benchmark.py run --output work/benchmark.json
```

Пример собирает бинарник из текущих исходников, создаёт отдельную память,
записывает контрольные решения, проверяет прямое чтение и поиск.
Он не запускает модели. [Замеры и методика](benchmarks.md).

## Идея из статьи или лекции

```text
/faust-mode Изучи <источник>. Сопоставь тезисы с текущими правилами fstack
и примерами ошибок. Предложи изменение, его более простой вариант и проверку,
которая позволит решить, стоит ли принимать изменение.
```

Проверь первичный источник и наличие проблемы в проекте. Идея может уже быть
реализована, относиться к другим задачам или ухудшать соседний сценарий.
[Как проверять такие изменения](evaluations.md).
