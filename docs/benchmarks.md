# Бенчмарки fstack

Здесь опубликованы измерения настоящего нативного runtime. Они показывают стоимость
его команд на конкретной машине. Качество решений агента проверяется отдельно
по [протоколу экспериментов](evaluations.md).

## Нативный runtime

<!-- benchmark:runtime:start -->

Замер 2026-11-14 · Windows AMD64 · данные соответствуют текущим измеряемым файлам.

11 повторов после одного прогрева; 256 записей памяти.

| Сценарий | Медиана, мс | p95, мс | Проверка результата |
| --- | ---: | ---: | --- |
| Прочитать известное решение | 231.029 | 233.921 | Пройдена |
| Найти известное решение | 698.636 | 731.567 | Пройдена |
| Проверить отсутствие решения | 705.827 | 726.505 | Пройдена |

[Все замеры и параметры](benchmarks/runtime-windows.json).

<!-- benchmark:runtime:end -->

Каждый замер запускает отдельный процесс. Время включает запуск бинарника,
чтение файлов, выполнение команды и проверку ответа. Перед каждым сценарием
есть один незачётный прогрев. p95 вычисляется по ближайшему верхнему рангу;
при 11 повторах это максимальный замер. Стоимость первого запуска и влияние
дискового кэша отдельно этим экспериментом не устанавливаются.

Корпус памяти синтетический и открытый: записи создаются штатной командой
`memory remember`. Один запрос должен найти ровно одну контрольную запись,
другой должен вернуть пустой список. Быстрый неверный ответ останавливает прогон.
Подготовка корпуса не входит во время поиска. Прямое чтение и поиск проверяют
также сохранность полного текста решения. Прогон использует временный каталог, отдельные профиль
и vault. Сами замеры работают без сети; первая сборка и установка toolchain
могут потребовать скачать зависимости.

## Повторить измерения

Нужны Python 3.11+, Git и [Rust 1.90.0 с системным toolchain](development.md#минимальные-проверки).
Скрипт сам собирает release из проверяемых исходников и получает путь к бинарнику
из вывода Cargo. Передать старый бинарник вместо этой сборки нельзя. Сборка не
входит во время команд:

```bash
python tools/fstack/benchmarks/benchmark.py run --output work/benchmark.json --samples 11 --records 256
```

Команда одинакова на Windows, Linux и macOS. JSON содержит все повторы, параметры,
окружение, SHA-256 бинарника и измеряемых исходников. Сравнивай варианты на одной
машине с одинаковым корпусом и нагрузкой. Повтори серии, если разница сопоставима
с разбросом. Один прогон не доказывает ускорение на других машинах.

## Актуализация

Каждая проверка пакета в Linux CI запускает этот же сценарий и прикладывает
`runtime-benchmark` к [workflow](https://github.com/WhyFaust/fstack/actions/workflows/release.yml).
Артефакт содержит результат своей ревизии; CI не изменяет ветку от имени автора.

Чтобы обновить опубликованный Windows-замер, используй
`--output docs/benchmarks/runtime-windows.json`, затем:

```bash
python tools/fstack/benchmarks/benchmark.py report
python tools/fstack/benchmarks/benchmark.py report --check
```

Генератор пересчитывает агрегаты из сырых данных и отмечает расхождение хешей
runtime, шаблонов памяти или измерительного скрипта. Проверка пакета и доступность
навыков не входят в эти измерения. CI отклоняет несогласованную таблицу.
Можно оставить исторический результат со статусом "устарели", пока новый замер
ещё не выполнен. Дату и числа вручную не исправляют.

Поведенческие эксперименты требуют новых запусков после существенных изменений
правил, моделей или среды. Зелёная проверка этой таблицы не подтверждает качество
новой конфигурации агента.
