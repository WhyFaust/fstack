# Бенчмарки fstack

## Первый запуск с пустым кэшем

Цель для рабочего соединения с GitHub — `p95 ≤ 10 с` от открытия чата
до успешного первого запроса с готовым координатором. Жёсткий предел хука
открытия — 15 секунд. При сбое последовательность загрузки заканчивается
сообщением, и чат остаётся доступным для обычной работы.

С опубликованными бинарником и SHA-256 текущего пакета выполни:

```bash
python tools/fstack/evals/check_skill_invocation.py /absolute/path/to/package --codex /absolute/path/to/codex --cold-samples 20 > cold-start.json
```

Каждый замер создаёт чистый профиль и качает runtime из GitHub. В отчёте
`open_seconds` — время до ответа App Server об открытии треда, `ready_seconds` —
до завершения первого запроса с локальным ответом-заглушкой. Проверка
подтверждает активацию на первом запросе и сохранение режима на втором.
Сохрани платформу и условия сети рядом с отчётом. Для задержки в интерфейсе
Desktop замерь время до доступного ввода отдельно.

## Координатор

Скрипт собирает release из текущих исходников и запускает штатную команду
`fstack --package ROOT hook UserPromptSubmit` отдельным процессом для каждого
замера. Модель и клиент Codex в измерении не участвуют. Каждый ответ проверяется
по режиму, событию, путям пакета и составу индекса методов.

| Сценарий | Подготовка | Ожидаемый ответ |
| --- | --- | --- |
| `cold_inactive` | Новый изолированный профиль перед каждым замером | Режим выключен, индекс отсутствует |
| `explicit_activation` | Новый изолированный профиль и запрос `/faust-mode` | Постоянный режим включён, полный индекс совпадает с каталогом пакета |
| `warm_continuation` | Один заранее включённый чат, один прогрев вне выборки | Режим остаётся включённым, индекс повторно не передаётся |

Профили и рабочие папки создаются вне репозитория и удаляются после запуска.
Сборка, создание папок и начальное включение для продолжения исключены из
замеров. В замер входят старт процесса, файловый ввод-вывод, разбор ответа
и проверка его контекста. Холодный сценарий означает новый профиль и процесс;
кэш файлов ОС не сбрасывается. Это не замер первого скачивания runtime.

Сохраняются все времена и доказательства проверки каждого ответа: SHA-256
канонического JSON, размер контекста и число записей индекса. Медиана и p95
вычисляются по исходным временам; p95 берётся по ближайшему верхнему рангу.
При 11 повторах p95 равен максимуму, поэтому для устойчивого сравнения нужны
повторные серии.

## Повторить измерения

Нужны Python 3.12+, Git и [Rust 1.90.0 с системным toolchain](development.md#минимальные-проверки).

```bash
python tools/fstack/benchmarks/benchmark.py run --output work/benchmark.json --samples 11
python tools/fstack/benchmarks/benchmark.py report work/benchmark.json
```

Для явного выбора платформы передай `run --target TRIPLE`; бинарник должен
запускаться в текущей среде. Требуется не менее пяти замеров каждого сценария.

JSON формата `schema: 2`, `kind: coordinator` содержит параметры, среду,
ревизию Git, признак отслеживаемых правок и SHA-256 бинарника, runtime,
каталога с методами и измерителя. Если входы изменились во время запуска,
результат не сохраняется. `report` проверяет полноту сценариев, исходных замеров,
сведений об ответах и совпадение агрегатов. Иной формат он отклоняет.

Сохраняй JSON вне отслеживаемых файлов. Сравнивай варианты на одной машине
при одинаковом числе методов, параметрах сборки и нагрузке. Если разница близка
к разбросу, повтори серии. Проверки измерителя запускаются так:

```bash
python -B -X utf8 -m unittest discover -s tools/fstack/benchmarks -v
```
