# Явное включение fstack

В новом чате координатор и роли fstack выключены. Одобренные хуки
независимо ведут [память проекта](memory.md).
Для полного процесса начни сообщение с `/faust-mode` и добавь задачу.
Равнозначные формы: `$fstack:faust-mode` и `$faust-mode` в начале сообщения.
Это текстовая команда fstack, а не обещание отдельного пункта slash-меню клиента.
В выборе навыков доступен `fstack:faust-mode`.

Одного вызова достаточно для всех следующих сообщений в этом чате.
Чтобы вернуться к обычной работе, начни сообщение с `/faust-mode-off`.
Повторный `/faust-mode` снова включит режим. Другие чаты не затрагиваются.
Цитаты, блоки кода, приложения
и упоминание команды в середине текста его не включают. Отдельный явно вызванный
метод, например `$fstack:review-change`, выполняется без включения координатора.

## Как устроено отключение

- Все навыки имеют `policy.allow_implicit_invocation: false`. Клиент не должен
  выбирать их по сходству темы. В активном режиме методы доступны по ссылкам
  из каталога пакета, даже когда они скрыты из неявного каталога клиента.
- Общий пользовательский `AGENTS.md` не создаётся и не обновляется. Hook
  распознаёт команду и передаёт путь к `skills/faust-mode/SKILL.md`, где
  находятся инструкции координатора.
- Одобренный UserPromptSubmit хранит отметку о включении по идентификатору
  чата в локальном состоянии fstack. Для включения подключать vault не нужно.
  SessionStart не добавляет контекст и не сбрасывает отметку. В обычном чате
  UserPromptSubmit подбирает память без загрузки инструкций координатора. При каждом новом
  вводе прежняя операция того же хода отменяется. В Plan режим действует,
  автоматическая память пропускается.

Плагин всё ещё установлен, поэтому клиент может запускать пустые хуки и хранить
его метаданные. Это не отключает собственные инструкции Codex, другие плагины,
глобальную память клиента и независимые требования проекта. Для сравнения модели
совсем без плагинов нужен отдельный профиль Codex; fstack не меняет его сам.

## Переход со старого профиля

После обновления пакета выполни Setup или явно вызови `$fstack:fstack-setup`
для синхронизации профиля. Helper однократно удалит прежний блок fstack, если
он совпадает с сохранённым хешем состояния `schema: 1`, и побайтно сохранит
остальной текст. Изменённый или отсутствующий блок остановит миграцию
с конфликтом. Новое состояние `schema: 2` управляет только ролями; последующие
обновления не читают и не записывают общий `AGENTS.md`. Начни новый чат:
уже загруженные инструкции и хуки старого пакета из текущего контекста не исчезнут.
В проектах с собственным безусловным требованием fstack согласуй его с новым
условием включения. При обновлении состава ролей примени [правила миграции
профиля](codex.md#миграция-набора-ролей).

## Проверка

Регрессии runtime проверяют обычный запрос, явные команды, цитаты, Plan,
продолжение в том же чате, выключение и изоляцию чатов. Проверка установки подтверждает
обнаружение навыков и метаданных клиентом. Codex CLI 0.157.1 не возвращает
политику вызова в skills/list; отчёт оставляет implicit_invocation: not_verified.
Политика проверяется по YAML пакета, а автоматический выбор модели не проверяется.
Проверка установки не выполняет модельные задания
и не доказывает качество исполнения инструкций.

Контракты клиента: [политика вызова навыков](https://learn.chatgpt.com/docs/build-skills),
[события хуков](https://learn.chatgpt.com/docs/hooks).
