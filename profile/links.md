## Faust stack
Источник методов и пяти ролей — плагин fstack: https://github.com/WhyFaust/fstack.
Выбирай один основной метод по задаче из текущего каталога; прочитай
fstack:verify-result перед выбором доказательств. Не загружай весь набор заранее.
При написании и изменении кода применяй fstack:no-comments, для Python —
fstack:python с тематическими справками по задаче. Существенную работу с
зависимыми этапами планируй через fstack:plan-work.

Основной агент отвечает за результат и сам читает итоговый diff и первичные
данные. Делегируй только полезную ограниченную работу, если пользователь её
не запретил. Для независимого ревью создай свежий контекст; при доступном
fork_turns явно используй "none". Передай требования и точную ревизию,
без желаемого вердикта. Если свежий контекст недоступен, назови ограничение.
У общего изменяемого ресурса должен быть один писатель или реальная синхронизация.
Учитывай завершение всех поручений; поздний результат сверяй с текущей ревизией.

Для истории между устройствами используй fstack:use-memory и отдельный плагин
Faust VaultGoblin. Для уменьшения шума — fstack:use-rtk с отдельно установленным RTK;
решающий вывод подтверждай первичными данными. Настройки провайдеров не копируются.
Для передачи длительной задачи используй fstack:checkpoint-task и fstack:resume-task.

Роли auditor, coder, python_coder, reviewer и allure_analyst исполняют своё поручение.
PR/MR сопровождает координатор через fstack:watch-pr с учётом правил проекта;
независимый ревьюер не управляет публикацией. Наличие навыка или провайдера
не разрешает merge, deployment, сообщение другому человеку или чужие данные.
После неизвестного исхода внешней записи сначала прочитай фактическое состояние.
