# fstack

Личный плагин Codex. Пиши документацию и инструкции навыков по-русски.

## Оркестрация

Оркестрация и навыки fstack включаются для текущего чата командой
`/faust-mode` в начале сообщения и действуют до `/faust-mode-off`.
Пока режим выключен, выполняй задачи напрямую с учётом требований
репозитория ниже. В активном режиме
используй `fstack:faust-mode` и `fstack:delegate-work`. [Карта инструкций](docs/orchestration.md) указывает,
где хранятся правила каждого слоя.

## Контракт репозитория

- `skills/` — небольшие законченные методы для координатора и доступных агентов Codex. Сохраняй явные границы применения. Согласованную смену опубликованного имени оформляй как breaking change с инструкцией перехода. Новый навык выделяй для самостоятельного результата, а не для каждого абзаца.
- `.codex-plugin/plugin.json` — манифест; `.agents/plugins/marketplace.json` — каталог.
- Навык и его справки должны работать из установленного пакета без доступа к clone.
- В активном faust-mode для создания, переноса или улучшения исходников навыка применяй
  `$fstack:adapt-skill`. Нужные устойчивые правила, примеры и справки из внешних
  материалов излагай своими словами в репозитории и включай в пакет. Ссылайся
  на эти материалы относительными путями. В пакете сохраняй необходимые
  лицензии и уведомления об авторстве в `licenses/`, без обзоров чужих проектов.
  Используй реальные адреса
  нужных API и инструментов и сверяй меняющиеся контракты с первоисточником
  при разработке.
- В README, документации и инструкциях не указывай фиксированное количество навыков. В диагностике вычисляй его по каталогу.
- `skills/faust-mode/SKILL.md` содержит правила явно вызываемого координатора. Пакет выбирает исполнителей среди всех доступных в сессии агентов и передаёт им нужные навыки. Миграция удаляет прежние файлы только по сохранённым хешам владения. Личные настройки Codex принадлежат пользователю.
- При изменении кода намерение выражается именами и структурой; необходимые лицензии, директивы и контрактная документация сохраняются.
- Выполни обязательные команды из раздела [Минимальные проверки](docs/development.md#минимальные-проверки).
- Runtime и проверки реализуются в `tools/fstack/` на Rust. Храни минимальные детерминированные регрессии рядом с кодом, без внешней сети, модельных evals, тестов формулировок и отдельных тестовых фреймворков. Не ослабляй проверяемый контракт. Пользователь получает готовый платформенный бинарник; не требуй Python или Cargo при установке и запуске.
- Перед merge подготовь версию манифеста и идентификатор сборки командой `release prepare`. CI сверяет версию с базой PR, а идентификатор с входами сборки. Автор PR
  отдельно повышает `metadata.version` каждого содержательно изменённого
  навыка по SemVer. Новый навык начинает с `1.0.0`. Во всех локализациях
  навыка указывай одну версию. Не редактируй установленный кэш.
- Сохраняй исходные уведомления об авторстве. Не добавляй личные настройки,
  токены, browser state, журналы чатов и данные рабочих проектов.
- Не запускай сценарии сравнения конфигураций без отдельного запроса.
- При любом изменении проверяй связанную документацию по всему репозиторию:
  README, `docs/`, инструкции навыков и профиля, примеры, команды, ссылки и схемы.
  Обновляй все затронутые материалы в том же PR. Не меняй непричастные файлы
  ради формальности; соблюдай инструкции вложенных `AGENTS.md`.
- В документации сохраняй устойчивые контракты и воспроизводимые способы
  настройки. Состояние поручений, текущие ветки и отчёты храни в PR/MR или
  согласованном приватном месте, а локальные значения оставляй в конфигурации среды.
- Изменение поведения навыка или роли оформляй как `fix:` либо `feat:`, даже если это Markdown. Несовместимость публичного имени, интерфейса скрипта или схемы профиля требует SemVer breaking change.
- Notion и RTK — отдельные компоненты. Пакет памяти содержит код и шаблоны Obsidian. Записи vault и локальные привязки проектов хранятся вне репозитория fstack.
